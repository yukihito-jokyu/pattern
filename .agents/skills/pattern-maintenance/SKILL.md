# パターンの追加・更新

ルートの`AGENTS.md`、`docs/project/contributing.md`、`docs/project/review.md`、`docs/project/verification.md`を読み、変更対象と既存のパターンを確認する。

- 文書は`docs/<分野>/<分類>/<パターン>/index.md`、実装は`patterns/`の同じ相対パス。運用文書は`docs/project/`。配布実装をサイト自身の実行コードへ流用しない。
- `docs/project/templates/index.md.template`から文書を作る。中心部分では実ファイルと親キーを含むコード、意味、動作、他の処理との関係、理由をつなげる。注意点はレビュー項目の条件に該当するときだけ書く。
- 説明用画像は対象文書の`images/`にPNGで配置し、相対参照と代替テキストを付ける。不要なら作らない。
- 実装にREADME・実ファイル・`verify.mjs`をそろえる。READMEはZIP単体での利用手順。検証は準備失敗で止め、未対応環境を成功にしない。
- 文書に対応ZIPへのリンクを置く。ZIPは手動編集せず生成コマンドを使う。改名・削除でも両側と参照元を確認する。

配置・文書確認、管理処理のテスト、型検査、サイトビルド、対象パターンのZIP展開後の検証、ブラウザー検証を行う。実際の文書を開き、サイドバー、本文、PNG、取得したZIPの中身まで確認する。自動テストは文章の妥当性を保証しないためレビュー項目も確認する。

文書に確認日・環境・期待結果・実際の結果を残す。報告は実装済み、自動検証済み、人間の確認待ち、未実施と理由を区別する。スキルを使ったこと自体を根拠にしない。ルール変更時は関連手順・テンプレート・検証処理も更新する。

Issueへの投稿・クローズやサイト公開は、このスキルの起動では許可されない。ユーザーの依頼範囲に従う。
