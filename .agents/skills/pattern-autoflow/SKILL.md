# pattern-autoflow

パターンの移行・追加・更新を、既存autoflowの状態機械で進める。このスキルを使う依頼は、下記の役をサブエージェントへ委任する依頼として扱う。独自の状態管理や承認の代行はしない。

## 最初に読む

ルートを基準に`AGENTS.md`、`.agents/skills/pattern-maintenance/SKILL.md`、`docs/project/autoflow.md`を読む。実装や検証の担当者にも読ませる。全役に、対象パスに適用されるAGENTS.mdを確認させる。

補助CLIは`python3 .autoflow/autoflow.py`。現在の設定に対応する承認がなければ`$autoflow-setup`へ進む。同じリポジトリの別タスク・別worktreeでも同じ設定の承認を引き継ぎ、承認記録のコミットや持ち運びを求めない。未コミットの編集や未追跡の移行元があっても、そのまま開始する。CLIが開始状態を記録し、開始後の差分をレビュー・承認・コミットの対象にする。AIは既存変更を保持し、利用者に事前のコミットや退避を求めない。準備不足はAIが依頼の範囲で解消し、人の判断が必要な場合は具体的な問題と対応案を示す。

## 依頼を受け付ける

- `resume <実行ID>`ならstartをせず、同じIDでstatusから再開する。
- 文章なら、受け取った文章をそのまま`.autoflow/runs/intake.md`へ書く。最初の行を題名にし、`start --source text --title <題名> --body-file <ファイル>`を実行する。
- `github <番号>`なら、このリポジトリを対象に本文・全コメント・URLを取得し、原文をintake.mdへ保存する。`start --source github --ref <番号> --url <URL> --title <題名> --body-file <ファイル>`を実行する。別リポジトリが明示されたら、その指定に従う。
- 他サービスが明示された場合だけ、`.autoflow/references/sources.md`の取得方法を使う。取得に失敗したら推測で補わず止まる。課題の取得は投稿の許可ではない。

引数はシェルの1引数として安全に渡す。本文はファイルを使い、コマンド文字列へ埋め込まない。startが返す実行IDを以降に使う。

リポジトリ内の実装を正規配置へ移行する依頼では、移行元の片付けまで計画と完了条件に含める。移行先・ZIPとの内容対応と単体動作を確認し、固有の記録を作業ツリー外へ保全してから不要な移行元を取り除く。開始前からあった未追跡ファイルであることを保持理由にしない。コピー依頼・保持指定・リポジトリ外の参照元はその指定に従う。H3へ進む前に、移行元が残らない command 条件と保全先を確認する。

## statusに従って進める

`status --run <実行ID>`を実行し、1つの処理が終わるたびにstatusへ戻る。

| 出力 | Codexで行うこと |
| --- | --- |
| `対象:`・`段階:` | 現在地として読み、必要な進捗を伝える |
| `次: <CLIコマンド>` | 指定のコマンドを実行する。verifyの実行中はツールのセッションを保持し、完了まで待つ |
| `job <役名> <ラベル> <プロンプト>` | 下表の役として、新しい独立したサブエージェントを起動する |
| `その後:` | その段の全jobが完了し、指定先に出力された後でだけ実行する |
| `人:`・`選択:` | 承認対象と選択肢を提示し、実際の人の回答を待つ |
| `終了:`・`WARN ` | 結果・制限として報告する |

CLI出力にあるAgent・AskUserQuestionは元キットの用語。Codexでは、利用可能なサブエージェント機能とユーザーへの確認に読み替える。Claude Codeのツール名やsubagent_typeは指定しない。

各jobは、生成されたプロンプトを読んでそのまま実行させる。役名は論理名であり、Codexのカスタムエージェント登録は不要。モデルは現在の設定を引き継ぐ。

| 役名 | 担当と書き込みの範囲 |
| --- | --- |
| `autoflow-planner` | 計画。プロンプトが指定する計画JSONだけを書き、実装を変更しない |
| `autoflow-builder` | 計画範囲の実装と報告JSON。共通基盤・スキル・プロファイル・検査設定を変更しない |
| `autoflow-risk` | リスク判定。指定の判定JSONだけを書き、規則によるリスクを下げない |
| `autoflow-finder` | 観点ごとの探索。指定の候補JSONだけを書く |
| `autoflow-verifier` | 候補の独立検証。指定の投票JSONだけを書く |

レビューと投票は別のエージェントにする。空き枠の範囲で起動し、枠不足なら残りを順に起動する。全jobが終わる前にcollectやtallyへ進まない。委任機能がなければ、独立レビューを親が代作せず、段と再開方法を示して停止する。出力に不足があれば同じ担当へ修正を依頼し、親が票や検査結果を書き換えない。

役のプロンプトは`.autoflow/templates/prompts/`から生成する。`.agents/`・`.autoflow/`を、実行中の実装役に変更させない。変更が必要ならblockersへ書き、H2で判断する。

## 人の判断と終了

人の関所の条件・選択肢・レビューの票数は`.autoflow/references/gates.md`を読む。人へ、対象ファイルへのリンク、要点、未確認事項、選択肢を示す。

- H1ではゴール・範囲・受け入れ条件・未決事項、H2では停止理由と失敗・指摘を示す。
- H3では文書・README・対象サイト・ZIP・検証ログを確認できる形で示し、人が読む差分と未確認事項を伝える。highなら2人目のレビューを頼むかも確認する。
- 回答がない・空・質問が閉じられただけなら承認にしない。対象と再開方法を示して止まる。
- decideには人の実際の選択と回答原文を渡す。H3承認後だけCLIのcommitを実行し、承認した版との一致をCLIに確認させる。

報告では実装済み、自動検証済み、人間の確認済みを分け、コミットIDまたは停止段、報告書の場所、未決事項、再開方法を示す。push・公開・Issue投稿やクローズは明示された依頼の範囲でのみ行う。
