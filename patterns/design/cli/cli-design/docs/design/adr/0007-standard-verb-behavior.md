# 0007 標準の動詞の振る舞いを決め、edit に値を消すオプションを置く

- 状態：採用
- 関係するルール：STATE-02、NAM-07、CODE-04

## 背景

収束テストのラウンド1では、3つの課題で9人のエージェントが同じ仕様（`cli.json`）を書いた。一方で、9人の報告には、仕様に書く場所が無く実装に任される点が共通して挙がった。

- `list --tag a --tag b` が「両方を持つもの」か「どちらかを持つもの」か
- `edit --tag` が「置き換える」か「足す」か
- `--sort` で `null` を先頭と末尾のどちらに置くか、範囲の絞り込みで `null` の行を含めるか
- 空を許す項目（`color`、`due_date`）を、`edit` で空に戻す方法が無い

仕様の形が同じでも、ここが決まっていなければ、実装の言語や作者ごとに CLI の振る舞いが分かれる。この基盤のゴール（誰が設計・実装しても同じ CLI になる）に届かない。見本の実装はこれらを1通りに実装していたが、ルールにも適合テストにも書かれていなかった。

真偽値の項目にも同じ穴がある。`--no-<name>` の書式は DEP-03 で使わないため、`edit` で `false` に戻せない。

## 選択肢

値を消す方法について：

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 消せないことをルールにする | 仕様の形が変わらない | 付けた期限・色を外せず、利用者が困る |
| 空文字（`--color ""`）で消す | オプションが増えない | `date`・`enum`・`integer` の値に空文字という例外ができ、型の検査（ERR-03）が型ごとに分かれる |
| `edit` に `--clear-<項目>`（`boolean`）を置く | どの型でも同じ形で、全言語の標準ライブラリで解析できる。生成器が機械的に置ける | オプションが増える |

振る舞いについて：

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 実装に任せる | ルールが増えない | 言語・作者ごとに振る舞いが分かれる |
| 決定表で決め、適合テストで確かめる | どの言語の実装も同じ振る舞いになり、違えば `make conform` で落ちる | 適合テストの項目が増える |

## 決定

- `edit` に、`nullable`・`list`・`boolean` の項目ごとの `--clear-<項目名の _ を - に替えた名前>`（`boolean`）を必ず置く。これは NAM-07 の決定表に入れたので、`make command`・`make field` が足す
- 標準の動詞の振る舞いを STATE-02 の決定表で決める。見本の実装の振る舞いを正とし、次のものを含む
  - 絞り込みは AND で組み合わせる
  - `edit` の値は置き換える
  - `null` は並べ替えで末尾に置き、絞り込みでは含めない
  - リストの値は重複を除いて昇順にする
  - 消した `id` を再利用しない
- `tools/clispec conform` が STATE-02 を確かめる

## 理由

`--clear-<項目>` は、値を取らない真偽値のオプションなので、DEP-03 の5つの書式の中で表せる。項目の型によらず同じ形になるので、生成器が型を見ずに機械的に置ける。振る舞いを適合テストで確かめれば、ルールを読み飛ばした実装も `make conform` で落ちる。

## 影響

- `edit` を持つ名詞では、`nullable`・`list`・`boolean` の項目を足すと、`--clear-<項目>` も一緒に増える
- 実装者は、STATE-02 の決定表を、実装用スキルの `references/stdlib-mapping.md` の「標準の動詞の振る舞い」に従って実装する
- 振る舞いを変えたくなったら、この ADR を置き換える ADR を書き、STATE-02、`tools/clispec/conform.py`、見本の実装を変える（PROC-04）
