# 0005 ヘルプの文面を仕様から生成し、適合テストで実装を確かめる

- 状態：採用
- 関係するルール：OPS-05、TEST-01、DEP-02、DEP-03、DEP-04、ERR-02、ERR-03

## 背景

設計（仕様）が同じでも、実装の言語が違えば外から見える動作が分かれる。実測では、同じ定義のオプションに同じ入力を与えても、Go の flag・Python の argparse・Node.js の util.parseArgs で次の差が出た（research.md「引数解析器の実測」）。

- ヘルプの出力先（Go は stderr）、書式、色（Python 3.14）
- エラーの出力と終了コード（argparse は usage と `error:`、Node.js は例外）
- 前方一致の省略（argparse は既定で受け付ける）
- `-name value` の解釈

設計の基盤が実装の言語を決めない以上、この差は仕様の側で吸収し、実装を外から確かめる必要がある。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 解析器の自動のヘルプとエラーに任せる | 実装が楽 | 言語ごとに出力が変わる |
| 仕様からヘルプの文面を生成し、実装はそれを出す。実装は外から適合テストで確かめる | どの言語でも同じヘルプ・終了コード・出力になる | 実装者が言語ごとの補い方を知る必要がある |

## 決定

2つ目を採る。

- `tools/clispec gen` がヘルプの文面を `cli.md` に書き、実装はそれを1文字も変えずに stdout に出す（OPS-05）
- 仕様が約束する引数の書式を、全言語で同じ結果になる共通部分だけにする（DEP-03）
- `tools/clispec conform` が、実装を一時ディレクトリで外から実行し、ヘルプ・版・終了コード・stderr の形・`--json` の形・表の見出しを確かめる（TEST-01）
- 言語ごとの補い方は、実装用スキルの `references/stdlib-mapping.md` に1つずつ決める

## 理由

外から見える動作を1つの文面と1つのテストに集めれば、実装者の言語の選択が設計の結果に影響しない。見本の実装（`tools/clispec/tests/fixtures/notes_impl.py`）に適合テストをかけ続けることで、適合テスト自身が壊れていないことも `make check` で確かめられる。

## 影響

- 見本の実装は、変わらないリリース済みの仕様（`specs/notes/released/1.0.0.json`）を対象にする。見本の仕様の変更が見本の実装に波及しない
- 適合テストが確かめられるのは、仕様から導ける項目だけである。業務の正しさ（並び順、絞り込みの意味）は実装側のテストで確かめる
