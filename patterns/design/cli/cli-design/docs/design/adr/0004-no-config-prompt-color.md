# 0004 設定ファイル・プロンプト・色を持たない

- 状態：採用
- 関係するルール：STATE-01、OPS-01、OPS-02

## 背景

clig.dev は、設定ファイル（プロジェクト・ユーザー・システム）、TTY のときだけのプロンプト、`NO_COLOR` などで消せる色を推奨している（research.md「Command Line Interface Guidelines」）。しかし、設定ファイルの形式（TOML・YAML・JSON）、TTY の判定、色の付け方は、言語ごとに標準ライブラリの対応が違う。Go・Rust の標準ライブラリは TOML・YAML を読めず、Node.js と Rust は TTY の判定の書き方が異なる。

指示は「引数の解析は標準ライブラリだけ」「どの言語でも対応可能」である。言語によって標準ライブラリで作れない機能を仕様に入れると、その言語の実装は外部パッケージを足すか、機能を落とすことになる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| clig.dev どおりに設定ファイル・プロンプト・色を持つ | 利用者に親切 | 言語ごとに実装が分かれ、標準ライブラリだけでは作れない言語がある |
| どれも持たず、値はオプション → 環境変数 → 既定値で決める | 全言語の標準ライブラリで同じ動作になる | 毎回オプションを渡す手間が利用者に残る |

## 決定

2つ目を採る。確認が要る操作はプロンプトではなく `-f/--force` で表し、色と進捗は出さない。データを保存する CLI は、データの置き場を `<PREFIX>_DATA_DIR` → XDG → `$HOME/.local/share` の順で決める（STATE-01）。

## 理由

同じ環境で同じ入力を与えたとき、どの言語の実装も同じ出力になることを、適合テスト（ADR 0005）で確かめられるからである。

## 影響

- 依頼が設定ファイルを求めた場合、この基盤のルールでは設計できない。PROC-04 の順で ADR を書き、ユーザーの承認を得る
- 環境変数は「同じ名前のオプションの既定値を変えるもの」と `<PREFIX>_DATA_DIR` だけになる
