# 0008 配布パターンのCI設定を基盤直下に置く

- 状態：採用
- 関係するルール：STR-01、PROC-04、TOOL-03

## 背景

この基盤を`design/cli/cli-design`の配布パターンとして利用・検証できるようにする。掲載リポジトリの共通CIは、パターン直下の`ci.json`から実行環境と検証コマンドを読む。しかしSTR-01の配置検査は、そのファイルも未知の実装として拒否する。

## 決定と理由

直下の許可名に、CI用メタデータ`ci.json`を追加する。個別検証は隠しディレクトリ`.ci/`に置く。CLIの実装は引き続き基盤の外に置き、`specs/<name>/`の3種類のファイルという制約は維持する。CIのために基盤全体をさらに子ディレクトリへ移す案は、利用者の実行場所や既存の相対参照を増やすため採用しない。

`.ci/verify.py`は一時仮想環境へuv 0.13.3を導入し、起動したPython 3.14をuvにも使わせる。既存のuvの有無で準備が分かれず、利用者のPython環境にはパッケージを追加しない。全検査、見本2種類の適合テスト、代表的な違反4件の検出、READMEに示す新規仕様の生成を確認する。準備に失敗したら後続を実行しない。

## 承認と影響

[Issue #11の計画](https://github.com/yukihito-jokyu/pattern/issues/11#issuecomment-6294187142)に対応する。ユーザーは会話で、`ci.json`を許可する配置ルール変更を含む計画に対し「issueへ登録し、対応してください」と依頼し、「developmentじゃなくてdesignでは？」と配置を修正した。共有可能な会話リンクはない。

- 配布側のルール、検査、違反例、生成した対応表、AGENTS.md、実装・レビュースキル、構造図を同期する。
- 元資料の`cli-design/`、見本のCLI仕様とリリース済みの内容は変更しない。
- 過去のprobe結果と収束評価は開発記録であり、今回実行した検証と区別する。配布側のprobe結果は更新した違反例で再検証する。
- ZIPの検証環境はmacOS/Linux、Python 3.14、GNU Make、ネットワーク接続とする。Windowsでの検証は本パターンに含めない。
