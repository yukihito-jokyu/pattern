# 0002 既存Motionへ接続し、仕様と実UIの検証を分ける

- 状態：採用
- 日付：2026-10-24

## 背景

取り込み先のcobaltは既に7つの時間Tokenと設定・停止・位置変化の機構を持つ。new-yorkは別のToken/APIを使う。新しい汎用エンジンを足すと、既存のAPIと状態、配布が二重管理になる。

## 決定

既存の機構を再利用する。JSONで意図・システム・recipe・頻度・ラベルを表し、正本Tokenへ対応させる。同じ作者入力から同じ適用計画を生成する。形を機械で確認できる部分を本基盤が検査し、実UIの意味と操作、人間の快適さは別の確認として残す。

Node 22を既存CIに合わせ、Pythonはfoundationの標準ライブラリ検査に限定する。Playwrightは検証用の依存だけ。周辺のアニメーションライブラリーは加えない。

## 代案と影響

全UIへ100〜400msを強制する案は、既存Tokenを壊し、ばね方式にも当てはまらないため採らない。型・schemaが通っただけで快適さを宣言する案も採らない。設定と状態・方向の意味は外部アプリの既存ルールを調べる必要がある。

持ち運ぶスキルには必要なツールと参照資料を同梱し、基盤ルールのコピーは生成して同期する。対象repoへ設計履歴を置けない場合は、外部一時ディレクトリで適用仕様を作る。
