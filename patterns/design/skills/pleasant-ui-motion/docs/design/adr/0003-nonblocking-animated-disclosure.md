# 0003 開閉の動きを保ち、次の操作を待たせない

- 状態：採用。初版のMOT-05とADR 0002から導いた即時閉鎖の判断を置き換える
- 日付：2026-10-24

## 背景

初版は、既存Cobaltが即時閉鎖することを理由に、開くときは透明度だけを補間し、閉じるときはhiddenを設定した。高さは瞬時に変わり、往復の動きがつながらなかった。自動テストも即時hiddenを正解にしていたため、この問題を検出できなかった。

ユーザーから「ぱっぱっと切り替わってアニメーションぽくない」「またないとはユーザーの次の動作がある場合、アニメーションによって待ち時間が発生しないという意味です」「アニメーションをなくすのは違います」と指摘を受けた。速さだけで成立する要件として扱った解釈を修正する。

## 決定

通常設定では開く・閉じる両方の高さと透明度を連続させる。開閉の意図は入力時に更新し、表示の補間と別に扱う。逆操作は表示中の状態から反転し、別の操作と必要なフォーカス復帰は演出完了を待たせない。閉じる内容はinertとaria-hiddenで操作対象から外し、退出する表示を残す。OS reduceと明示OFFは目標状態へ確定し、ON復帰だけで再演しない。

参照実装は非モーダルDisclosureとし、CSS Gridの0fr/1frとopacityをtransitionで補間する。完了イベントによる状態更新や入力ロックを持たないため、古い完了処理から開閉状態が巻き戻る経路を作らない。Cobaltは高さ変化の役割に合う既存expand（260ms）、new-yorkは既存normal（180ms）を使う。時間だけの短縮を解決策にしない。位置・サイズの連続を検証し、速度まで連続する物理ばねとは呼ばない。

## 影響と検証

disclosureのinterruptionはreverse、exitはanimated-nonblockingへ変更する。スキル・レビュー・ルール・生成物・README・掲載文書を同時に更新する。通常設定の往復で中間状態があること、4回の途中反転で端点へ飛ばないこと、退出中に別ボタンを押せること、フォーカス・入力保持、低減設定を検証する。入力を遅らせる違反と、通常時に演出を削除する違反の両方をprobeへ加える。

取り込み先の固定スナップショットが同じ挙動を持つとは主張しない。実UIへの適用時は既存の正本・存在管理・Portal・フォーカス・背面の操作制限を確認し、原本・Story・Registry・利用スキルへ反映する。今回の変更対象は本パターンであり、取り込み先本体は変更していない。新しい動きの気持ち良さは、人が実際に触って確認する。
