# 気持ち良さを実装判断へ変える

人は操作すると、入力が届いたこと、何が変わったか、結果、次にできることを知りたい。これらの間に空白や矛盾があると、自分でUIを操作している感覚が弱くなる。この関係を支える動きを、ここでは「気持ち良い」と捉える。これは設計上の仮説であり、心理学的に確立された単一の法則ではない。

## 基本品質と遊び心

| 原則 | 見るもの | 具体的な判断 |
|---|---|---|
| 即応性 | 開始遅延と継続時間を別々に見る | 押下で受理、処理中は状態表示。演出のための待ちを足さない |
| 連続性 | 対象・位置・因果のつながり | 同じ選択面は途中位置から次へ。無関係な画面は短いフェードも選べる |
| 意図との一致 | 操作目的と実際の結果 | 保存成功は実処理から決め、失敗・再試行も伝える |
| 自然な運動 | 距離・大きさ・速度・方向・停止 | 既存Tokenと意味のある方向を使う。物理模倣を目的にしない |
| 操作の主導権 | 待機・中断・最新目標 | 動きは保ち、逆操作・次の入力・フォーカスを終端イベントへ依存させない |
| 情緒的な報酬 | 場面・頻度・可読性 | 低頻度の確定済み成功だけを一度祝う。既定は無効 |

Reduced Motion、キーボード、動き以外のラベルは全項目に横断する前提とする。「よく弾む」ことで未達を相殺しない。5つの基本品質に未達があれば改善し、遊び心は加点して帳消しにしない。

## 時間をどう選ぶか

ユーザーが挙げた押下80〜150ms、hover/toggle100〜200ms、出現150〜250ms、モーダル200〜300ms、拡大/遷移250〜400ms、祝福200〜400msは独自の初期範囲である。本パターンは既存デザインシステムの値を優先し、この範囲へ無断で揃えない。

NN/g（2020）は一般論として100〜500ms、多くの場合100〜400ms、単純な反応は約100ms、モーダルは200〜300msと説明する。Microsoftの50ms以内という開始目安はWindows 7向け資料で、全Web UIの合否規格ではない。開始遅延・演出時間・非同期処理時間を混同しない。

Material 1のResponsive/Natural/Aware/Intentionalは歴史的な整理として使う。現行Material 3は2025年からばね方式へ移行している。ばねの速度・減衰と固定durationは別の設計であり、既存のCSS曲線をばねと呼ばない。Cobaltのease-springは名前にspringを含むcubic-bezierで、物理シミュレーションではない。

## レビューの進め方

入力の受理、結果の意味、関係の追跡、停止・反転・再目標化、動きを止めた代替表現、反復利用の順に実操作する。中断可能・反転可能・再目標化可能は異なる能力である。本パターンの開閉は、通常設定では往復のアニメーションを保ち、途中で逆操作できることを確認する。短縮だけに頼らず、ユーザーの次の動作を先に受け付ける。調査時点のCobaltの即時閉鎖は既存実装の事実であり、今回の目標ではない。Tabsの位置変更は別の再目標化として扱う。

既存10項目チェックリストは実装レビュー用の独自表として使えるが、検証済みの採点尺度や利用者満足度の測定値にしない。主要な未達、観測条件、修正内容を残し、人が反復して触る確認を別に受ける。
