# 質問と回答の扱い

最初に質問範囲を選んでもらい、その範囲で用途、サイト名、公開ドメインと配信パスから聞く。その後は区分ごとに現在値・未設定・既定値を示す。型の和訳だけで済ませず、例えばbaseUrlなら「https://example.com/manual/で配信するなら/manual/」と入力と結果を説明する。台帳に説明がない項目は出典の対象版を読み、推測で効果を説明しない。

台帳のimportanceはimportant（重要）、normal（普通）、advanced（あまり見なくてよい項目）の3段階。質問範囲importantは重要のみ、normalは重要と普通、advancedはすべてを含む。分類理由はimportanceReason。OSSの必須指定requiredとは別の、このパターンでの導入判断の分類である。現在は重要12パス、普通を含め83パス、全体900パス。親子・型分岐や非該当を含むため、そのまま質問回数にしない。分類の保守元はsetup/lib/question-levels.mjs、配布される定義はsetup/settings.catalog.json。

initは範囲内をunanswered、範囲外をretainedで記録する。retainedは個別に確認した回答ではなく、選んだ質問範囲に従って現在値・未設定時の既定動作を維持する状態。valuesには開始時の値、reasonには維持する理由が入る。confirmedへ一括変換しない。範囲外を変更する必要が出たら、その項目の効果と値を提示して個別確認し、該当する全IDをconfirmedへ更新する。範囲外の親構造は、確認済みの子だけを変更してよい。validateは元のファイルと比較し、未確認の変更を拒否する。

利用者が各項目について現在値を維持するか、変更するか、キーを省略して既定動作にするかを選ぶ。null、false、空文字、空配列、キー省略を区別する。親オブジェクトを省略すると子の状態も変わるため、子項目を含めた値を提示する。

回答ファイルのquestionLevelは選んだ範囲、settingsは最終的に保存する値。reviewsのキーは台帳のidであり、decisionはunanswered、confirmed、not-applicable、retained。confirmedには利用者が確認した最終値をvaluesへ配列で保存する。値が存在しない場合は[]。値の抽出はsetup/lib/setup.mjsのlistingが行うため、手でハッシュを推測する必要はない。

同じpathに型分岐の異なるidがある。無効な機能や不一致の分岐をnot-applicableとする場合はreasonを必ず記載し、利用者へ非該当理由を示す。forbiddenは廃止項目であり設定しない。未設定と非該当は違うため、キーがないだけで非該当にしない。

利用者に提示して回答を得た範囲だけ、listing(catalog, answers.settings)のcurrentをreviews[id].valuesへコピーし、decisionを更新する。確認後に値が変わった項目は再確認する。選択範囲内の親オブジェクトも最終値の確認対象になる。validateは選択範囲の未回答や確認後の値の変更を拒否する。

関数やコードは `{"$module":"./local-options.cjs","export":"handler"}` 形式で参照できる。ローカルにある、利用者が選択した信頼できるモジュールだけを使う。CLIの検証・反映時やサイト起動時にNode.jsで読み込まれる。文字列をコードとしてevalしない。モジュールを自動生成して機能の意味を推測しない。

無効な機能を有効にしたときは、その子項目と追加コンテンツ・依存関係を質問する。ブログや翻訳などの全組み合わせをこの雛形が検証済みとは説明しない。秘密値を回答ファイルへ保存する必要がある設定は、環境参照モジュールなどで扱い、一覧・ログ・差分へ値を漏らさない。
