# skill-tune-kit 通し実行の記録

配布物を一時リポジトリに入れ、本物のサブエージェントで計画の承認から報告までを通した記録である。単体テスト（`tests/`）はサブエージェントの出力を `tests/support.py` の部品で作るため、サブエージェントが実際にプロンプトを読み、決めたファイルを書けるかは、この実行で確かめた。

## 条件

| 項目 | 値 |
|---|---|
| 日付 | 2026-10-21 |
| 実行方法 | 一時リポジトリで `claude -p "/skill-tune date-format .claude/skills/date-format …"`（Claude Code 2.1.296、`--setting-sources project,local`、`--permission-mode acceptEdits`、`--allowedTools Agent Read Glob Grep Write Edit "Bash(python3 .tune/tune.py *)"`） |
| 人が決める場面 | 無人で回すため、プロンプトで答えを先に与えた（計画は承認、データの直しは提案の全部を適用、最良の版は適用しない） |
| 対象スキル | `tests/fixtures/sample-skill/` を名前 `date-format` で置いたもの（日付を ISO 8601 にそろえる3行の手順） |
| モード | reference（正解の文字列と `equals` で比べる。weekday のグループだけ judge の検査 Q1 も当てる） |
| ケース | 10件（weekday 3、range 3、plain 4）。正解には、元のスキルに書いていない決まり「日付に添えた曜日を消す」「期間は両端を完全な日付にする」を入れた |
| 分割 | train 6（wd-trip、wd-deadline、rg-holiday、rg-campaign、pl-kanji、pl-yearless）、val 2（wd-meeting、pl-slash）、test 2（rg-training、pl-dot） |

## 経過

| 回 | サブエージェントの起動 | 結果 | 見つかった問題と対処 |
|---|---|---|---|
| 1（上限 1 ラウンド） | 実行役 13、採点役 6、監査役 1、学習役 1 | 段階: 完了まで進んだ。最良の版は v0 のまま | 監査役が、weekday の3件に一貫した「曜日を消す」決まりを「依頼が求めていない」として `expected` に分け、正解をスキルの出力に合わせる直しを出した。監査役のひな形に「他のケースと一貫した決まりはデータの意図とみなし `skill` にする」規則を足した（[ADR 0009](adr/0009-data-fix-with-human-approval.md)）。あわせて、`audit.py` にあった指示の文（STATE-02 の違反）をひな形に移した |
| 2（上限 2 ラウンド） | 実行役 8、採点役 3、監査役 2 | 1回目のラウンドの監査で止まった | 監査役は今度は曜日の2件を `skill`、依頼文の食い違い（wd-deadline）だけを `input` に分けた。ところが直しのケースに、証拠の見出しの分割名 `"split": "train"` を書き、元の値（空。自動の分割）と違うとして `audit-check` が2回続けて落とした。直しの `split` は元の値に戻すようにし（`contracts._parse_fix`）、テストを足した。呼び出し側のエージェントは同じエラーが2回続いたところで自分で止めたので、この止め方を skill-tune の「守ること」に書いた |
| 2 の再開 | 監査役 1、学習役 1、実行役 13、採点役 4 | 段階: 完了まで進んだ。1ラウンド目で v1 を採用し、検証用で全ケースに合格したので止まった | テスト用に weekday のケースが1件も無く、学習で直した点の効果をテスト用で測れなかった。plan.md に「グループが検証用かテスト用に1件も無い」警告を足し、dataset-guide.md の「どのグループも散る」という誤った記述を直した |

費用は、`claude -p` の結果の `total_cost_usd` で 1回目 1.33 ドル、2回目 0.77 ドル、再開 1.20 ドルだった。

## 2回目（再開後）の報告の要点

1回目のラウンドの比較（`rounds/r1/compare.md`）:

| 指標 | 今の版 v0 | 候補 v1 |
|---|---|---|
| 学習用の合格率 | 66.7% | 100.0% |
| 学習用の検査の通過率 | 75.0% | 100.0% |
| 検証用の合格率 | 50.0% | 100.0% |
| 検証用の検査の通過率 | 66.7% | 100.0% |

検証用で上がったのは wd-meeting（0% → 100%）である。学習役が見たのは学習用の wd-trip と wd-deadline の失敗だけで、v1 の SKILL.md には次の節が足された。

> 日付に添えた曜日（「(木)」「（火）」「Thu」など）は、その日付表記の一部として扱う。日付を書き換えるときに曜日ごと消し、YYYY-MM-DD だけにする。

テスト用（rg-training、pl-dot）は v0 も v1 も 100% で、報告の結論は「最良の版 v1 はテスト用の合格率が元の版と同じ。差分を読んで決める」になった。最良の版は適用せず（`apply --skip`）、`applied.json` に `"applied": false` が残った。

## この実行で確かめられたこと

- 4つのサブエージェントが、プロンプトのファイルを読み、決めた名前のファイル（`response.md`、`grade.json`、`proposal.json`、`audit.json`）を書けた
- `status` の行だけを頼りに、呼び出し側のエージェントが段を飛ばさずに進めた（`job` の行の並列起動、`その後:` の行、人が決める場面の行）
- データの直しの後、直したケースだけが古くなり、今の版で評価し直された
- 学習役は学習用の証拠だけから、検証用でも効く規則を足した。`learn-check` は検証用・テスト用の写しを検出しなかった
- 止める条件（検証用で全ケース合格）で止まり、最後にテスト用で v0 と最良の版を評価して報告した
