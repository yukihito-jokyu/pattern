# 0002 独立した役を4つのサブエージェントに分ける

- 状態：採用
- 関係するルール：STR-05、STATE-02、STATE-03

## 背景

依頼は「独立学習、独立検証を回し、スキルを改善する」ことである。ここで「独立」とは、スキルを直す者・スキルを使う者・結果を判定する者・評価データを点検する者が、互いの判断や会話の履歴に引きずられないことを指す。Claude Code のサブエージェントは新しい文脈で始まり、親の会話を見ない（research.md の「Claude Code のサブエージェント」）。そのため、役ごとにサブエージェントを分ければ、文脈の独立を仕組みで得られる。

一方、サブエージェントは AskUserQuestion を使えない。人に聞く場面はメインのセッションのスキルに残す必要がある。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| メインのセッションが全部を行う | 速い | 直した本人が判定するので独立していない。会話が長くなり、前の判断に引きずられる |
| `claude -p` で役ごとにセッションを起動する | 実際の利用に最も近い | 利用者ごとに権限の設定が要り、人の承認を挟めない。起動が重い |
| 役ごとにサブエージェントを定義する | 文脈が独立し、道具を役ごとに絞れる。追加の設定が要らない | パスの読み取りを仕組みで限定できない |

## 決定

3つ目を採り、次の4つの役を定義する。

| 役 | 名前 | 見るもの | 書くもの | CLAUDE.md |
|---|---|---|---|---|
| 実行役 | `tune-executor` | 版のスキル、ケースの依頼文、sandbox | sandbox の中の成果物、`response.md` | 読む（実際の使われ方に合わせる） |
| 採点役 | `tune-grader` | 依頼文、正解（使う検査だけ）、judge の検査、返答、sandbox の変更。版は知らせない | `grade.json` | 読まない |
| 学習役 | `tune-learner` | 今の版、学習用の証拠（evidence.md） | 候補の版、`proposal.json` | 読まない |
| 監査役 | `tune-auditor` | 失敗したケースの全情報 | `audit.json` | 読まない |

どの役も `tools` を列挙し、`Skill` と `Agent` を入れない。

## 理由

- 実行役が採点基準を知ると、基準に合わせた答えを書き、スキルの実力を測れない。だから実行役には依頼文だけを渡す
- 採点役が版（元の版か候補か）を知ると、候補をひいきしうる。作業場所の名前を版から作らない（`run-key` はハッシュ）ことで、版を伏せる
- 学習役が検証用・テスト用を見ると、採否とテストが暗記を測る（STATE-03）
- 監査役を学習役と分けるのは、「スキルが悪い」と「データが悪い」の判定を、直す側の都合から切り離すためである

## 影響

- 1ケースの評価で、実行役1回と、judge の検査があれば採点役1回が起動する。起動の回数は plan.md に見積もりとして出す
- サブエージェントが読めるパスを仕組みで限定できないため、学習役の候補は `learn-check` が検証用・テスト用の文の写しを検査する
- 役を足すときは `contracts.AGENTS`、`kit/claude/agents/`、SKILL.md の表を一緒に変える（PROC-02）
