# 0003 作業場所を .tune/ に置き、配布物の正本を kit/claude/ に置く

- 状態：採用
- 関係するルール：STR-01、OPS-04

## 背景

Claude Code は `.claude/` への書き込みを保護されたパスとして扱い、`permissions.allow` でも事前に許可できない（research.md の「Claude Code の権限と保護されたパス」）。学習役は対象スキルの写しを何度も直し、実行役は作業場所に何度も書き込む。これらを `.claude/` の下で行うと、そのたびに人の確認が要る。

また、この基盤自身も Claude Code で開発するため、配布物を `kit/.claude/` に置くと、この基盤の開発のセッションが配布物のスキルを読み込んでしまう。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 作業場所を `.claude/` の下に置く | スキルの近くにまとまる | 書き込みのたびに確認が要る |
| 作業場所を OS の一時ディレクトリに置く | リポジトリを汚さない | リポジトリの外を読む・書くたびに確認が要り、結果が消える |
| 作業場所を `.tune/` に置く | 確認が要らない。結果を残せる | リポジトリに `.tune/` が増える |

## 決定

- 補助 CLI、計画、評価データ、版、結果は `.tune/` に置く。実行役の作業場所は `.tune/work/` に置き、`install.py` が `.gitignore` に足す
- 配布物の正本は `kit/claude/`（先頭にドットを付けない）に置き、`install.py` が利用者のリポジトリの `.claude/` へ写す
- 対象スキルを書き換えるのは `apply` だけにする

## 理由

学習役と実行役の書き込みに確認が要らなくなり、ループが人の応答待ちで止まらない。結果を `.tune/targets/` に残すので、後から報告の根拠を辿れる。

## 影響

- 実行役は作業場所の外（`.tune/targets/` の評価データ）を読める位置にいる。読まないことはプロンプトで指示し、学習役の写しは `learn-check` で検査する
- `.tune/work/` は消してよい。結果は `.tune/targets/<id>/results/` に写してある
