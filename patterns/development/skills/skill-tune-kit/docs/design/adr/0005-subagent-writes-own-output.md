# 0005 サブエージェントの成果はサブエージェント自身がファイルに書く

- 状態：採用
- 関係するルール：STATE-02、CODE-06

## 背景

1回の改善のループで、実行役・採点役は数十回起動する。サブエージェントの返答はメインのセッションの文脈に入るため、返答が長いと文脈がすぐに埋まり、メインのセッションが要約で前の指示を失う。

実験で、サブエージェントは `report.md` という名前のファイルを書けない（「Subagents should return findings as text, not write report files.」）が、`response.md`、`grade.json`、`proposal.json`、`audit.json` は書けることを確かめた（research.md の「Claude Code のサブエージェント」）。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 返答の本文で受け取り、メインのセッションが保存する | 書けないファイル名の心配が無い | 返答が全部メインの文脈に入る。写すときに1文字でも変わると結果が汚れる |
| サブエージェント自身が決めた名前のファイルに書く | メインの文脈には「完了: <パス>」の1行だけが入る | 書けない名前を避ける必要がある。書き忘れを検出する必要がある |

## 決定

2つ目を採る。出力のファイル名は `layout` の定数にし、名前に `report` を含めない。返答は `完了: <パス>` の1行にさせる。書き忘れは `eval-collect`・`eval-score`・`learn-check`・`audit-check` が検出し、status が同じ job の起動をやり直させる。

## 理由

長いループでもメインのセッションの文脈が増えにくく、写し間違いも起きない。

## 影響

- サブエージェントに書かせるファイルの名前を足すときは、`report` を含めない（STATE-02）
- 書けない名前の条件は公開の文書に無い。Claude Code を上げたときに名前の制限が変わったら、この ADR を見直す
