# 0004 配布するスキルを1つにし、人が /skill-tune で呼ぶ

- 状態：採用
- 関係するルール：STR-05、PROC-07、STATE-01

## 背景

依頼は「スキルのブラッシュアップ、精度改善をするスキルを作って」で、利用者が呼ぶ入口は1つである。作業は「計画を人と決める」と「ループを回す」の2つに分かれるが、どちらにいるかはファイルの有無で決まる。

ループは長く、サブエージェントを何十回も起動する。Claude が会話の流れで勝手に始めると、人の知らないうちに費用がかかる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 計画用と実行用の2つのスキルに分ける | スキルごとの手順が短い | 利用者がどちらを呼ぶか迷う。2つのスキルの間で手順が食い違いうる |
| 1つのスキルにし、status の指示で手順を分ける | 入口が1つ。途中で止めても同じコマンドで続きから始まる | SKILL.md が長くなる |

## 決定

1つのスキル `skill-tune` にし、`disable-model-invocation: true` を付けて、人が `/skill-tune <target-id>` で呼ぶ形にする。手順は `status` の出力に従う表にし、計画の作り方の詳細は `references/` に分ける。

## 理由

入口が1つなら、利用者は「どこまで進んだか」を気にせず同じコマンドを打てばよい。status が次の手を決めるので、スキルは長くても、エージェントが読むのは今の段階に関係する節だけになる。

## 影響

- SKILL.md が500行を超えそうになったら、手順の詳細を `references/` へ移す（STR-05）
- 計画の作り方（正解データの作り方、評価項目の壁打ち）は `references/dataset-guide.md` と `references/criteria-guide.md` に書く
