# 0009 評価データの直しは監査役が提案し、人が承認したものだけを適用する

- 状態：採用
- 関係するルール：PROC-07、STATE-03、OPS-04

## 背景

依頼には「テストの正しさを思考し、問題があれば改善する」とある。正解の誤り、あいまいな評価項目、情報の足りない入力は、スキルを直しても失敗を生み続け、学習役に誤った方向を教える。受付で、直しは人の承認を得てから適用し、テスト用はループ中は固定すると選んでもらった。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 監査役の判断で自動的に直す | 速い | ゴール（正解や評価項目）がエージェントの判断で動く |
| 監査役が提案し、人が承認したものだけを直す | ゴールを人が握る | ラウンドごとに人の応答を待つ |

## 決定

- 毎ラウンドの初めに、今の版の学習用・検証用の失敗を監査役が点検する。失敗が無ければ監査を省く
- 監査役は失敗ごとに原因を `skill`（スキルの問題）、`expected`（正解の誤り）、`check`（検査があいまい・誤り）、`input`（入力の情報が足りない）のどれかに分け、`skill` 以外には直したケースか検査の全体を書く
- 人が適用する指摘を選び、`data-fix` が cases.json・plan.json に適用し、承認を記録し直す。直したケースの結果は古くなり、今の版で評価し直す
- テスト用のケースは直さない。最後にテスト用の失敗を監査役が点検し、指摘は報告に載せるだけにする
- 直しで `id`・`group`・`split` は変えさせない（分割が変わるため）
- 正解が依頼やゴールに書いていない決まりに従っていても、他のケースの正解と一貫していればデータの意図とみなし、原因を `skill` にさせる。見本スキルでの通し実行で、全ケースに一貫した「曜日の注記を消す」決まりを、監査役が「依頼が求めていない」として `expected` に分けたためである

## 理由

正解を変えることはゴールを変えることなので、人が決める。テスト用を直さないのは、テスト用を見てデータを変えると、最後の結果が独立でなくなるためである。

## 影響

- ケースの中身が変わったかは、結果に記録したハッシュで判定する。ハッシュが変わったケースは、実行からやり直す（採点だけのやり直しはしない。単純さを優先した）
- 人の応答が無い間、ループはデータの直しの場面で止まる
- 計画の検査（全ケースに当てる検査）を直すと、テスト用のケースの採点も変わる。直しはテスト用を見ずに学習用・検証用の失敗から決めたものなので許し、承認の記録（`test_changed`）と報告に残す
