# 0001 ルールを機械で強制し、独立エージェントで検証する

- 状態：採用
- 関係するルール：TOOL 節の全ルール

## 背景

この基盤のゴールは、同じ依頼を受けた別々の作者（人・エージェント）が同じ書き方をする状態を保つことである。文書に書いたルールだけでは、作者は読み飛ばし、忘れ、解釈を分ける。さらに、ルールを書いた本人には行間が見えているため、ルールが十分かどうかを自分では判定できない。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 文書でルールを示す | 作るのが速い | 守られたかどうかを確かめられない |
| 文書と人のレビュー | 意味の判断ができる | レビュアーごとに基準が揺れ、見逃しがある |
| 機械で強制し、独立エージェントで揺れを測る | 違反が書けない、または検査で落ちる。十分かどうかを測定で判断できる | 検査の仕組みと probe を作り、保守する費用がかかる |

## 決定

3つ目を採る。

- ルールはルールIDを付けて `docs/design/rules.md` に書く
- 各ルールを、できるだけ上の段の機械の仕組み（型、formatter、linter、構造検査、テスト）で縛る
- 機械で縛ったことは、違反例（`.foundation/probes.json`）で証明する
- 独立エージェントに同じ課題を解かせ、書き方の違いを測って締め込む

## 理由

機械の検査は、作者が誰であっても同じ判定をする。違反例で証明しておけば、設定の誤りで検査が効いていない状態に気づける。独立エージェントでの計測によって、「ルールが十分か」を書いた本人の感覚ではなく、測定結果で判断できる。

## 影響

- ルールを変えるときは、rules.md、検査の設定、probe、参照実装を一緒に変える必要がある（手順は AGENTS.md）
- 検査の設定ファイルと `.foundation/` は保護ファイルとして扱う。エージェントが編集しようとすると、hooks がユーザーに確認を求める
- 検査用スクリプト（`.foundation/bin/`）は Python 3 の標準ライブラリだけで動く。実行には python3 が必要である
