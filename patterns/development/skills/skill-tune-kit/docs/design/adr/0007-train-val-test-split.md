# 0007 ケースを学習用・検証用・テスト用に分け、テスト用は最後に1回だけ使う

- 状態：採用
- 関係するルール：STATE-03

## 背景

依頼は、正解データがある・作れるなら学習用・検証用・テスト用の入力と正解を作り、独立学習と独立検証を回し、最後にテスト用で測って報告することである。スキルの改善でも機械学習と同じく、直すときに見たデータで測ると、改善の実力ではなく暗記を測ってしまう。

正解データが無い場合も、評価項目（検査）を壁打ちで決めた後に、入力を3つに分ければ同じ仕組みで独立性を保てる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 分けずに全ケースで直して測る | ケースが少なくても回せる | 合わせすぎを検出できない |
| 学習用と検証用の2つに分ける | 採否は独立に決まる | 採否のために何度も使った検証用は、最後の結果としては楽観的になる |
| 学習用・検証用・テスト用の3つに分ける | 最後の結果が一度も見ていないデータで測られる | ケースが最低3件、実用には10件以上要る |

## 決定

3つに分ける。

- 分け方は決定的にする：ケースを `group` ごとに `sha256("<seed>:<id>")` の順に並べ、group を名前の順に1件ずつ交互に取り出した列を作り、各ケースを「目標の件数との差が最も大きい分割」（同点ならテスト用、検証用、学習用の順）に割り当てる。目標の件数は、検証用とテスト用が `round(総数 × 比率)`（最低1）、学習用が残り（最低1）である
- ケースの `split` で分割を固定できる（利用者が既にテスト用を持っている場合）。固定したケースも目標の件数に数える
- 既定の比率は 0.6・0.2・0.2、seed は `skill-tune`
- 学習役には学習用だけを見せる。テスト用は、ループが終わった後に元の版（v0）と最良の版を1回ずつ評価する
- 総数が3件未満なら計画を受け付けず、10件未満なら plan.md に警告を出す

## 理由

分け方を決定的にすると、同じ計画からは誰が回しても同じ分割になり、報告から再現できる。group ごとに交互に取り出すのは、ケースの種類が分割に偏らないようにするためである。

## 影響

- ケースの `id`・`group`・`split` を変えると分割が変わる。データの直し（data-fix）ではこの3つを変えさせない
- テスト用のケースの中身を、承認の後に変えると、報告に「テスト用が変わった」と書かれる
