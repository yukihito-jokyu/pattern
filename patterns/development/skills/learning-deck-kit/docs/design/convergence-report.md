# learning-deck-kit 収束テストの記録

同じ依頼を、基盤の作成履歴を持たない3人へ渡して比較する。比較対象は教材の追加、既存例の変更、全教材の出典更新であり、最終回だけ関数例の変更も加える。各人は独立したコピーで作業し、他者の出力を読まない。生の指標と差分は`.foundation/convergence/round-<R>/`に保存する。

## 条件と実行方法

| 項目         | 値                                                                                    |
| ------------ | ------------------------------------------------------------------------------------- |
| 方式         | greenfield、教材・専用スキル生成器の基盤                                              |
| 正式な実行   | Agentツール、fork_turns=none、1課題につき新しいセッション、親と同じモデルを継承       |
| 人数と課題   | 通常回は3課題×3人、最終回は未使用課題を加え4課題×3人、最終レビューは別の3人           |
| 課題         | `.foundation/convergence/tasks.json`。依頼の本文は全回同じ                            |
| 閾値         | files=1.0、names≥0.8、content≥0、全員check成功、保護対象の変更なし                    |
| 上限         | 正式3ラウンド。未使用課題はラウンド3で初めて使用                                      |
| 実行環境     | Node 22.23.4、Python 3.14。コピー内build/temporaryをTMPDIRに使う                      |
| コピーの除外 | 前回の差分・課題一覧・レビュー正解表・probe結果を渡さない。依存は準備済みリンクで参照 |

最初はmanifestの`claude -p`を試したが、通常回の途中で5時間枠のHTTP 429となった。未変更コピーまで一致と数えた値は採用せず、正式な比較から外す。中断した記録は`round-0-cli-interrupted/`に残す。正式回は新しいコピーとAgentツールでやり直した。この代替ではClaude Codeの自動hookは動かないため、保護ファイルの変更をdiffで別途検出する。hook自身の保護確認と編集後整形は、別の一時コピーで実行している。

ラウンド1では最初の3人へ同じNode実行パスと依存リンクの扱いを補足した。ラウンド2からprepareがその環境説明を全員の初期プロンプトへ入れる。ラウンド3では一時領域もprepareが作り、場所を全員へ明示する。ネットワーク制限時の依存取得とブラウザ実行は、ツール実行として同じコマンドを権限付きで再試行できる旨を同じ条件で補足する。これらは環境の補足であり、変更ファイルや実装方法のヒントは渡していない。

## ラウンド2で直したこと

全課題でファイル集合が一致し、保護対象を変えた人もいなかった。変更・横断は内容まで一致した。追加は同じ7ファイルを変更し、教材IDとデータの形も一致した。

一方、手順がTMPDIRをtest-results/authoringへ置くと、Playwrightがtest-resultsを初期化して一時領域も消した。各作者は生成物用の別の場所へ移し、検査を緩めずに成功させた。これはR1（出力の所有者が未決定）として、TMPDIRをbuild/temporary、保持する証跡をbuild/verification、Playwrightだけをtest-resultsへ分けた。prepare、AGENTS、impl、READMEをそろえ、修正後の全検査・違反例・規則対応を通してから最終回を準備した。詳細はADR 0005にある。

追加課題のnames=0.361で一部の作者だけが新しく使った語は、deck.md内の英語資料名や構図の記述だった。公開関数、教材ID、キー名が分岐した結果ではない。文章の意味を同じにすることはPROC-02で求めるが、自由な説明の英単語まで固定するルールは加えず、R7として受け入れる。生の0.361と閾値未達は残し、指標を水増しするために語彙を基準へ加えることもしない。

## 結論と人間に残す判断

既存変更と横断更新は全3回で内容まで一致した。追加の変更ファイル集合は0.630から1.000へ改善し、保護対象の変更は解消した。最終回の全12check、要求事実の照合、全レビュアーの8件検出は成功した。

一方、新しい注目対象の選択・命名というR1が1件残り、追加課題のnamesも0.8へ届かない。**基盤全体が収束合格したとはしない。** 未使用課題のfiles差は取得記録に対応するR7として受け入れるが、生の指標は残す。

作成に使ったpattern-foundation SKILL.mdのフェーズ6は「既定の上限は3ラウンドである。上限に達した場合は、残った揺れをすべて分類して報告する」と定める。上限に達したため4回目は行わない。現在の基盤を使いながら意味のあるローカルIDを許すか、上表の正規名と選択条件まで固定して追加比較するかが、人間に残る判断である。

## 判定の限界

この比較は、同一の基盤から同一の依頼を解いた結果であり、すべての技術や将来の作者の振る舞いを保証するものではない。check成功と教材内容の人間による承認も区別する。比較中に作者が追加した教材は測定用であり、配布する参照教材には加えない。測定には追加のcritic用スロットを設けていないため、作者の新規教材について独立スライド批評は未実施として残す。参照スライドの独立批評と残った余白の指摘は、別の`reference-review.md`に記録する。
