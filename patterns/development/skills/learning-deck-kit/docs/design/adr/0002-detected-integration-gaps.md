# 0002 実際の対象と検査範囲を合わせる

- 状態: 採用
- 日付: 2026-10-25

統合レビューで、コメント内のtarget文字列とslide-previewクラスが実要素として誤受理されること、狭幅の矢印が別カードの本文を横切ることを再現した。静的スライドのタグと属性を読む際にコメント・raw textを除外し、classは空白区切りのトークンとして一致させる。ブラウザではガターへ線を迂回し、複数幅と長いカード本文で重なりを検査する。

違反probeでは抑止コメントが検査を通ることも分かった。配布元guard.pyの既定除外が.claude全体で、今回のruntime配置まで除いていたためである。キットへコピーしたguardだけはこの除外を削除し、vendorの除外はmanifestで限定する。配布元のスキル原本は変更しない。runtime内の実際の抑止コメントをprobeに使い、正しい理由で落ちることと全検査への組込みを証明する。

いずれも新しい要件を追加する変更ではなく、既存のNAM-01/STR-01、OPS-03、TOOL-02を実装へ反映する修正である。実測・回帰と独立確認を根拠にし、検査の成功だけで意味や人間の学習体験まで承認済みにしない。

最終probeのbaselineでは、縦配置の検査がリサイズ中に差し替えられたSVGを読む競合も1回再現した。検査はDOM内で要素を選び、その同じ評価内で接触を測る。描画途中の要素なしを安全とせず、再描画を待つ値として扱う。修正後に該当操作20回が成功した。製品の表示条件や失敗の判定基準は緩めない。

参照教材を2行のコードへ絞った後、SVGの注目番号が前のコード行を覆う表示も画像で発見した。位置を横へずらすだけでは390pxで再現するため、Range.getClientRectsとtext.getBBoxから実文字・番号の矩形を測り、近い空白へ配置する。白い縁と他の番号も含め、スライド内へ収める。全項目・全枚・3幅で検査し、文字の障害物を無視するOPS-03-bを違反例へ追加した。余白が見つからない場合は誤った注目表示を残さずエラーを通知する。
