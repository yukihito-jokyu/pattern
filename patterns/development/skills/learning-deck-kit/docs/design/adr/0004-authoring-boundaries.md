# 0004 教材データ変更の境界を固定する

- 状態: 採用
- 日付: 2026-10-25

通常ラウンド1の教材追加では、本文や構図は一致する一方、1人はREADME/AGENTSの項目数を書き換え、2人は保護対象の.claude/skillsへ生成スキルを追加した。うち1人はブラウザ検査へ項目名を追記した。生成台帳のハッシュ値まで新しい識別子に数えられ、namesの低さは教材の名前の違いではなく生成物の混入に起因していた。これはR1（変更範囲と出力先が未決定）とR5（全項目の検査が手動列挙）である。

PROC-02の正本をprofile/lesson/deckへ固定し、データだけの変更ではREADME/AGENTSを変えない。初期参照と当時の実測を現在の項目一覧に見せず、一覧・期待出力はデータから読む。確認用生成スキルはbuild/skills、ページはbuild/siteへ出す。buildは共通ZIP生成でも除外される。ブラウザ検査はprofileを列挙するため、教材追加で検査コードへ手を入れない。

JSON用hookがCLIのJSON.stringify整形、完了検査がPrettierという二つの書式も衝突した（R2）。sourceの正規整形をPrettierへ統一する。生成物と所有台帳を手で合わせて解消する手順は認めない。一時作業と証跡はtest-results/authoringへ置き、生成物を正本に混ぜない。

隔離制約に合わせてTMPDIRをコピー内へ移した1人は、親のtype:moduleが拡張子なし検査fixtureへ伝わる失敗を発見した。fixture自身にtype:commonjsを持たせ、置き場所に依存させない。検査を緩めず、コピー内TMPDIRで既存テストが通ることを確認する。コードを変更した実測日と資料を再取得した確認日の区別もPROC-02へ明記する。

文章の言い換え、見出しの長短、正しい要素同士での注目箇所の選択は、契約と読みやすさを満たす範囲でR7として受け入れる。書き方をそろえるために、教材の意味を一字一句固定する生成器は追加しない。
