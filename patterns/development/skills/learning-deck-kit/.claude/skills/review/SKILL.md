# レビュー手順

## 1. 対象を決める

指定があればその差分、なければgit diff HEADと未追跡を確認する。未コミットがなければ基準ブランチとの差分を対象にする。対象ファイルを明記する。

## 2. 機械の検査を回す

npm run checkを実行し、失敗と未実施をそのまま報告する。機械で検出した内容を人手指摘として重複させない。
途中で検査が失敗しても、残りの差分の読み取りは続ける。未実行の検査を成功とは書かない。機械の失敗にはルールID・場所・実際の記述を添え、意味の指摘と区別する。

## 3. 抜け道を確かめる

| ルールID | 確認方法                                  | 違反の典型例                         |
| -------- | ----------------------------------------- | ------------------------------------ |
| DEP-02   | manifest.protectedと依存・ADRの差分を照合 | 検査を通すため設定を緩める           |
| TOOL-02  | 抑止コメント、skip/only、テスト削除を確認 | 失敗するテストをskipにする           |
| TEST-01  | テストのassertと書込先を確認              | ログだけで成功扱い、本物の教材を書換 |

## 4. 機械で拾えないルールを確かめる

| ルールID | 確認方法                                                                                | 違反の典型例                           |
| -------- | --------------------------------------------------------------------------------------- | -------------------------------------- |
| STR-02   | 責務の分割：差分の責務と参照実装を照合する。                                            | 規則の決定と差分の実際の記述が食い違う |
| DEP-02   | 依存と保護面の変更：manifest.protected と差分・ADRを照合する。                          | 規則の決定と差分の実際の記述が食い違う |
| NAM-02   | 意味を示す名前：新しい識別子の役割と用語表を照合する。                                  | 規則の決定と差分の実際の記述が食い違う |
| CODE-03  | コメントと数値：公開関数のJSDocと新しい数値の意味を確認する。                           | 規則の決定と差分の実際の記述が食い違う |
| OPS-01   | 対象版と出典：モデルがURLと日付と版を検査し、レビューで実際の取得内容と説明を照合する。 | 資料を取得せず確認済みとする           |
| TEST-01  | 意味のある検証：検査の対象とassertと書込先を確認する。                                  | 規則の決定と差分の実際の記述が食い違う |
| PROC-02  | 教材変更の波及：変更シナリオ表の両側を開いて内容を照合する。                            | 例の値と期待出力が食い違う             |

## 5. ファイルをまたぐ対応を確かめる

PROC-02：profileの版と順序をlessonの説明・deck・Go例の出力・生成スキルの資料一覧へ照合する。targetが存在するだけでなく、説明した意味の箇所を指しているか読む。意味に影響しない言い換えだけで差し戻さない。
データだけの変更ではREADME/AGENTSと保護面を変えていないか、確認用の生成先がbuild/skillsかを確認する。所有台帳の手編集や、変更したコードへ古い実測日を流用する記載を認めない。

新規ファイルも含めて責務を確認する。真偽値にはis/has/canの接頭辞があるか、公開export関数のJSDocに各@paramと@returnsがあるか、追加assertが振る舞いの失敗を検出するかを具体的な行で確かめる。資料の取得を省く例外や、型・lintを抑止する記載が説明文へ入っていないかも読む。

## 6. 出力の形式

判定はcheck成功かつ指摘0なら承認、それ以外は差し戻し。場所の順に指摘する。IDを挙げるだけでなく実際の記述を引用する。

```text
# レビュー結果
## 判定
承認 または 差し戻し
## 対象
対象ファイル一覧
## 機械の検査
実施結果と未実施理由
## 指摘
| # | ルールID | 場所 | 根拠（実際の記述） | 直し方 |
|---|---|---|---|---|
指摘がなければ「なし」
## ルール追加の提案
規則にない気づき。なければ「なし」
```
