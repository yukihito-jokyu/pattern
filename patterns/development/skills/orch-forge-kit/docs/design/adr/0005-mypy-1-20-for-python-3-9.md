# 0005 型検査は mypy 1.20.2 を使い、Python 3.9 を対象にする

- 状態：採用
- 関係するルール：CODE-03、TOOL-05、PROC-03

## 背景

配布物は、対象のリポジトリの `python3` で動く必要がある。開発の環境の `python3` は 3.9.6 で、配布先にも 3.9 が残っている可能性がある。型検査の対象の版は 3.9 にしたい。

PyPI の mypy の最新は 2.4.0 だが、`requires_python` が `>=3.10` で、`python_version = 3.9` を対象にできない（[research.md](../research.md) の「mypy」）。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| mypy 2.4.0 で `python_version = 3.10` | 最新の版を使える | 3.10 以降の API を使っても検査で落ちず、配布先の 3.9 で落ちる |
| mypy 1.20.2 で `python_version = 3.9` | 3.9 に無い API（`zip(strict=True)` など）を検査で落とせる | 最新の版ではない |
| 配布物を 3.10 以上に限る | 最新の mypy を使える | 3.9 の環境では補助 CLI が動かない |

## 決定

mypy 1.20.2 を `uvx mypy@1.20.2` で呼び、`python_version = 3.9`、`strict` にする。

## 理由

型検査で 3.9 に無い API を落とせることが、配布物が任意のリポジトリで動くことの直接の保証になる。`uvx` が自分の環境を用意するので、開発の環境の `python3` が 3.9 でも使える。

## 影響

- mypy を上げるときは、対象の版を 3.10 に上げるかを同時に決める（PROC-03）
- ruff は `target-version = "py39"` にそろえる
