# 0003 配布物の正本は kit/claude に置き、評価用のコピーはリポジトリの外に置く

- 状態：採用
- 関係するルール：STR-01、STATE-01、OPS-04

## 背景

この基盤には、置き場を決める必要のあるものが3つある。

1. 配布するスキルとサブエージェントの正本。開発で編集する
2. 評価用のコピー。実行役（`claude -p`）がその中で対象スキルを動かす
3. 記録（charter、設計、採点、提案、比較、決定、報告）と、実行の記録などの中間のファイル

Claude Code では `.claude/` への書き込みは保護されたパスで、`bypassPermissions` 以外では自動で許可されない。また、CLAUDE.md はファイルシステムのルートから作業ディレクトリまでの全階層から読み込まれる（[research.md](../research.md) の「Claude Code の CLAUDE.md の読み込み」）。評価用のコピーを対象のリポジトリの中に置くと、実行役は元のリポジトリの CLAUDE.md とコピーの CLAUDE.md を両方読み込み、本番と条件が変わる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| コピーを `.forge/work/` の下に置く（先例の形） | 1か所にまとまる | 実行役が元のリポジトリの CLAUDE.md も読む。リポジトリの検査がコピーまで見て遅くなる |
| コピーを OS の一時ディレクトリの下に置き、記録と中間のファイルは `.forge/` に置く | 実行役の CLAUDE.md の条件が本番と同じになる | コピーの場所がリポジトリの外になり、探しにくい |

## 決定

- 配布物の正本は `kit/claude/`（先頭にドットを付けない）に置き、`install.py` が対象のリポジトリの `.claude/` へ写す
- 評価用のコピーは `<OS の一時ディレクトリ>/orch-forge/<リポジトリ名>-<リポジトリの絶対パスの sha256 の先頭8桁>/<target-id>/<slot>/<run-id>/` に置く。場所は `proc.copies_root` だけが求め、`cli` が `Layout` に渡す
- コピーからは `.forge/`、`.git/`、`forge-*` のスキルとエージェントを除く。`.forge/` にはホールドアウトを含む charter があるからである
- 記録は `.forge/targets/<id>/`、中間のファイルは `.forge/work/<id>/` に置く
- サブエージェントが書くのは `.forge/` の下だけにし、`.claude/` へ写すのは `install` と `decide --adopt` だけにする（OPS-04）

## 理由

実行役が本番と同じ CLAUDE.md を読むことは、評価の値を信じる前提である。コピーをリポジトリの外に置けば、対象のリポジトリの設定（`claudeMdExcludes` など）を変えずに済む。

## 影響

- コピーは OS が消すことがある。消えたコピーで `collect` を回すと、`StageError` で `prepare` からやり直すよう伝える
- `install.py` は `.forge/work/` を `.gitignore` に足す
- ユーザー単位の `~/.claude/` の設定・スキル・エージェントは実行役にも読み込まれる。本番の開発者と同じ条件として受け入れ、報告に書く
