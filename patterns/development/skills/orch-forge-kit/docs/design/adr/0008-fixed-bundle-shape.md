# 0008 生成するオーケストレーションスキルの形を固定し、決まりを bundle.RULES に置く

- 状態：採用
- 関係するルール：STR-06、PROC-02、TEST-03

## 背景

構築役と分析役は、対象スキル（SKILL.md と、役ごとのサブエージェントの定義）を書く。形が自由だと次の3つが崩れる。

1. 採点役が「手順に従ったか」「報告の形に従ったか」を判定するには、手順と報告の節が決まった場所にある必要がある
2. 実行の記録から起動を数えるには、サブエージェントの名前でバンドルのものと見分ける必要がある
3. 自動で呼ばれるスキルや、`Agent` を持つサブエージェントは、人の知らない間に起動を増やす（[research.md](../research.md) の「Claude Code のスキル」「Claude Code のサブエージェント」）

さらに、形の決まりがひな形・スキル・検査に別々に書かれると、構築役が読む決まりと検査が落とす決まりが食い違う。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 形を決めず、採点役に読み取らせる | どんなスキルでも評価できる | 判定が採点役ごとに揺れ、起動の数を正しく数えられない |
| 形を決め、決まりの文と検査を1つの表に置き、文書を生成する | 構築役が読む決まりと検査が一致する。採点と計測が決まった場所を読める | 既にある、形の違うスキルは、先に形をそろえる必要がある |

## 決定

- バンドルの決まりは `bundle.RULES` の表だけに書き、1行に id・文・検査の関数を置く。文書 `forge-build/references/bundle-rules.md` は `make docs` が生成する（STR-04、STR-06）
- 決まりの中身は次のとおりにする（文の正本は `bundle.RULES`）

  | 観点 | 決めたこと |
  |---|---|
  | 置き場と名前 | `skills/<スキル名>/SKILL.md`、`agents/<スキル名>-<役>.md`（1〜6個） |
  | frontmatter | スキルは `disable-model-invocation: true` で `context` を書かない。サブエージェントのキーは決まった集合だけで、`tools` は Read・Write・Edit・Glob・Grep・Bash の中から列挙する（`Agent` を入れないので入れ子を作らない） |
  | 本文 | `## 役割`・`## 手順`・`## 人に確かめること`・`## 報告`・`## してはいけないこと` の節。手順は番号付きの一覧。人に確かめることには、人が答えられないときの既定を書く |
  | 中身の整合 | SKILL.md が全サブエージェントの名前を書く。`TODO(forge)` を残さない。構築のときは承認した設計の役と道具に一致させる。評価課題の文を写さない |
- 既にあるスキルを forge-run で改善するときも、先に `bundle-check` を通す。通らなければ `status` が問題を示す

## 理由

形を固定すると、採点役は `## 手順` の各項目を判定項目にでき、計測は名前で起動を数えられる。決まりを1つの表に置けば、構築役が読む文書と検査が同じ変更で変わる（PROC-02）。

## 影響

- 決まりを足すときは、`bundle.py`、`make docs`、`tests/test_bundle.py` を同じ変更で変える
- 人に確かめる場面のある対象スキルは、実行役（人に聞けない）の評価では既定の答えで進む。既定の書き方が悪ければ、評価で失敗として現れる
