# 0004 配布するスキルは人が呼ぶ3つにし、段の判断は補助 CLI の status に置く

- 状態：採用
- 関係するルール：STR-05、OPS-01、PROC-07

## 背景

この基盤の作業は、ゴールを決める、初版を作る、評価して直す、の3つに分かれる。それぞれに人の関所（承認、採否）があり、段の数は合わせて20を超える。スキルの分け方と、どの段にいるかを誰が判断するかを決める必要があった。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 1つのスキルにまとめる | 呼ぶ名前が1つで済む | SKILL.md が500行を超えうる。ゴールを決め直すだけのときも全体を読む |
| 決める・作る・回すの3つに分ける | 1つのスキルの手順が短い。既にあるスキルの改善だけなら forge-build を飛ばせる | 3つの名前を覚える必要がある |
| 段ごとにスキルを分ける | 1つの手順がさらに短い | 名前が多く、順番を人が覚える必要がある |

## 決定

- スキルは `forge-goals`（ゴール・指標・評価課題を決める）、`forge-build`（サブエージェントで初版を作る）、`forge-run`（評価と改善を回す）の3つにする
- 3つとも `disable-model-invocation: true` にし、人が `/forge-goals` の形で呼ぶ
- どの段にいて次に何をするかは、補助 CLI の `status` がファイルの有無から決め、`段階:` の行に受け持つスキルの名前を出す。スキルは `status` の行に従い、自分の受け持ちでない段なら、人に別のスキルを呼ぶよう伝える

## 理由

3つの区切りは、人の関心の区切り（何を良いとするか、何を作るか、どこまで良くするか）と一致する。段の判断をエージェントに任せると、作者や実行ごとに手順が飛び、承認の前に評価を始めることがある。`status` に置けば、判断はテストできるコードになる。

## 影響

- 段を足すときは、`status` と、段を使うスキルの表を同じ変更で直す（PROC-02）
- 自動で呼ばれないので、人が呼ばない限り `claude -p` は起動しない
