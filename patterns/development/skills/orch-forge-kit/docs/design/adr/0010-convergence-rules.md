# 0010 収束テストで揺れた点のルールを足し、見本と食い違うルールを直す

- 状態：採用
- 関係するルール：NAM-02、CODE-01、CODE-06、TEST-03、PROC-02、PROC-06

## 背景

ルールを書いた本人には行間が見えているため、独立した作者が同じものを書くかは測るまで分からない。そこで、この基盤を初めて見るエージェントに同じ依頼を解かせ、書き方の違い（揺れ）を測った（経過は `docs/design/convergence-report.md`）。揺れの原因は次の2種類に分かれた。

1. ルールが何も決めていない点で、作者ごとに選択が分かれた（テストの置き場、古い記録の読み方）
2. ルールの文と、作者が真似る見本のコードが食い違っていた（関数名の動詞、引数の変更の禁止）

2 は、収束テストを始める前のレビューでも見つかった。見本のコードがルールに違反していると、レビュー役は見本を真似た変更を違反として指摘するか、ルールを無視するかで割れる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 見本をルールに合わせて全部書き直す | ルールの文は変わらない | 検証の部品（`problems` に足していく形）や、意味の名詞で始まる関数を作り直すことになり、変更が大きい |
| ルールの文を見本に合わせて絞り、決まっていない点に答えを足す | 見本はそのままで、ルールと食い違わない | ルールの文が長くなる |

## 決定

- NAM-02：語彙表の動詞は、表の意味の関数に使う。表の動詞と同じ意味の別名（`get_`・`fetch_`・`format_`・`create_`・`validate_`・`save_`）を禁じ、構造検査（`check_names`）と probe NAM-02-a で落とす。表に無い意味の関数は、名詞か表に無い動詞で始めてよい。`make_` は「値を組み立てて返す」にし、`cli.build_parser` を `make_parser` に直した
- CODE-01：検証の関数が受け取る `problems` に問題を足すことは、引数の変更の禁止の例外にする
- TEST-03：段とサブエージェントが受け渡す JSON（`contracts`）の項目を足したときの置き場を、`tests/test_contracts.py` の `test_parse_<名前>` にする。見本の `test_contracts.py` のメソッド名をこの形にそろえた
- PROC-02：既存のファイルに項目を足すだけなら、architecture.md のデータの流れの行がそのファイルの中身を書いていても変えない
- PROC-06：版を持たない JSON のうち `.forge/targets/` に残る記録に項目を足すときは、項目の無い古い記録を既定値で読む
- 実装用スキルの既定値表に、新しい指標の id、新しい置き換えの名前、段の入口に足す引数の位置、人の言葉を受け取る引数の値の扱いを足した
- 2回目の計測の後、既定値表に、置き換えの値が無いかの判定（`<値> or render.MISSING`。空文字だけを無い値とする）と、新しいテストのメソッドの位置（クラスの最後）を足した
- CODE-06：ファイル名の定数を `/` でつなぐのは `layout.py` の中だけにし、他のモジュールは `Layout` のメソッドで置き場を受け取る（バンドルの中の `SKILL.md` を除く）。構造検査 `check_paths` と probe CODE-06-b で落とす。レビュー用スキルの検出率の計測で、3人のレビュー役がそろって「置き場の作り方が決まっていない」と提案した点で、見本には違反が無いので、見本は変えない
- PROC-02：表に「人が決める charter のキー → `forge-goals/SKILL.md` の、そのキーを決める手順の表」の組を足し、レビュー用スキルの突き合わせにも足した。レビューの計測で3人がそろって提案した点で、実装の作者は3人とも既にこの組を変えていた（patterns.md の6節に従った）
- 3回目の計測の後、既定値表に、項目が取りうる値の一覧の定数の名前（項目の名前の複数形の大文字。前例は `PRIORITIES`、`METHODS`）と、ADR のファイル名（変える charter のキーか引数の名前の kebab-case）を足した。上限の3回に達したので、この2つの後は計測していない

## 理由

揺れは、ルールが決めていない点か、ルールと見本が食い違う点で起きた。決めていない点は、多数の作者が選んだ書き方と、既存の見本にある前例（`feedback` の置き換えの名前、`today` を最後に置く引数の並び）から答えを決めた。見本との食い違いは、ルールの目的（同じ意味の動詞が混ざらないこと、可変の値を段の間で渡し合わないこと）を保ったまま、文の範囲を見本に合わせた。

## 影響

- 新しい揺れが見つかったら、同じ手順（ADR → rules.md → 検査と probe → 見本）で足す（PROC-04）
- 語彙表の別名を増やすときは、`scripts/structure_check.py` の `SYNONYM_VERBS` と rules.md の NAM-02 を一緒に変える
