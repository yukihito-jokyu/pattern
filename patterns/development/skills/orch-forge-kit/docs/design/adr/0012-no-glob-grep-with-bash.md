# 0012 生成するスキルに Glob・Grep を前提にさせない

- 状態：採用
- 関係するルール：STR-06、PROC-02、TEST-03

## 背景

Claude Code は、macOS・Linux・WSL では Glob と Grep を既定のツールに入れず、ファイルの検索を Bash の `find`・`grep`（中身は組み込みの `bfs`・`ugrep`）で行う。Glob・Grep が戻るのは、起動の `--tools`・`--allowedTools` でどちらかの名前を挙げたときと、サブエージェントの `tools` に Glob・Grep を書いて Bash を外したときだけである（[research.md](../research.md) の「Claude Code のサブエージェント」）。

見本のリポジトリでの通しの実行（`docs/design/convergence-report.md`）で、構築役が書いたスキルは、メインのセッションの手順で「Glob で一覧する」と書き、さらに「Bash では検査のコマンドのほかを実行しない」と禁じていた。実行役の Claude Code（2.1.296、macOS）には Glob が無く、手順の遵守率が下がり、実行役が禁止に反した。人が画面で使うときも、macOS・Linux では同じことが起きる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 実行役の `--allowedTools` に Glob・Grep を足す | スキルを変えなくてよい | 評価のときだけ Glob・Grep があり、人が使うときの環境と違う。charter に無い許可を足す（OPS-05） |
| 設計役・構築役のプロンプトに注意を書く | 変更が小さい | 守られたかを確かめられない |
| バンドルの決まりに足し、設計の検査でも落とす | 構築の時点で機械が落とす。評価と普段の利用で同じ手順になる | 決まりが1つ増える |

## 決定

- バンドルの決まり B13 を足す。スキルのファイル（SKILL.md と references）に `Glob`・`Grep` を書かず、ファイルは Bash の `find`・`grep` で探すと書く。`Bash` を持つサブエージェントの `tools` と本文にも `Glob`・`Grep` を書かない
- 設計の検査（`design.parse`）も、`Bash` と `Glob`・`Grep` を一緒に持つ役を落とす。B11 で設計と構築の `tools` をそろえるので、設計の時点で止めないと構築役が直せない
- この道具のサブエージェント（設計役・構築役・採点役・分析役）は Bash を持たないので、`tools` の Glob・Grep が使える。変えない

## 理由

評価は、人が普段使う環境と同じ条件で測らないと意味が無い。そのため、実行役に許可を足すのではなく、どの環境でも動く書き方を生成物に求める。Bash を持たない役（レビュー役など）は Glob・Grep が使えるので、`tools` に入れてよい。

## 影響

- B13 より前に作ったスキルや、人が書いたスキルが B13 を満たさないときは、ほかの決まりと同じく、forge-run の `status` が「対象スキルがバンドルの決まりを満たしていない」で止め、人に直すかを相談する
- Windows では Glob・Grep が既定で使えるが、同じ決まりに従う（`find`・`grep` は Windows の Bash でも動く）
