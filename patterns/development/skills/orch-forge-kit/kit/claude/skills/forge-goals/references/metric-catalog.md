# 指標の一覧

charter の `metrics` に書ける指標である。`machine` は補助 CLI が実行の記録と差分から機械で数え、`grader` は採点役が判定する。
値は 0〜1 の割合（量の指標 `cost_usd`、`duration_sec`、`launches` を除く）で、課題ごとに求めてから平均する。

## `check_pass` 検査の通過率（推奨）

| 項目 | 内容 |
|---|---|
| 分かること | スキルに従って作ったものが、リポジトリの検査（テスト・lint・型など）を通るか |
| 求め方 | 実行ごとに、コピーで environment.check_command を回し、終了コード0だった実行の割合 |
| 測り方 | machine |
| 向き | 高いほど良い |
| 既定の閾値 | 1.000 |
| 前提 | environment.check_command |

## `acceptance` 受け入れ条件の充足率（推奨）

| 項目 | 内容 |
|---|---|
| 分かること | 依頼したことを、抜けなく満たしているか |
| 求め方 | 採点役が acceptance の各条件を満たしたかを判定し、満たした割合を実行ごとに出して平均する |
| 測り方 | grader |
| 向き | 高いほど良い |
| 既定の閾値 | 1.000 |
| 前提 | 各課題の acceptance（1件以上） |

## `protected_untouched` 保護パスの非変更率（推奨）

| 項目 | 内容 |
|---|---|
| 分かること | 検査の設定やルールの正本など、変えてはいけないファイルを変えずに済ませるか |
| 求め方 | environment.protected_paths の glob に当たるファイルを1つも変えなかった実行の割合 |
| 測り方 | machine |
| 向き | 高いほど良い |
| 既定の閾値 | 1.000 |
| 前提 | environment.protected_paths（1件以上） |

## `completion` 完了率（推奨）

| 項目 | 内容 |
|---|---|
| 分かること | 費用や時間の上限に達したり、エラーで止まったりせずに、最後まで終えるか |
| 求め方 | 実行の記録の result が success で、打ち切られず、終了コード0だった実行の割合 |
| 測り方 | machine |
| 向き | 高いほど良い |
| 既定の閾値 | 1.000 |
| 前提 | — |

## `delegation` サブエージェントへの委任率（推奨）

| 項目 | 内容 |
|---|---|
| 分かること | ファイルの編集を、メインのセッションではなく役ごとのサブエージェントに任せているか |
| 求め方 | 実行ごとに、編集（Edit・Write など）のうちサブエージェントが行った割合を出して平均する。編集の無い実行は数えない |
| 測り方 | machine |
| 向き | 高いほど良い |
| 既定の閾値 | 0.800 |
| 前提 | — |

## `flow_conformance` 手順の遵守率（推奨）

| 項目 | 内容 |
|---|---|
| 分かること | スキルの `## 手順` の各項目を、飛ばさず順に行ったか |
| 求め方 | 採点役が、実行の記録から手順の各項目を行ったかを判定し、行った割合を実行ごとに出して平均する |
| 測り方 | grader |
| 向き | 高いほど良い |
| 既定の閾値 | 1.000 |
| 前提 | — |

## `report_format` 報告の形式の遵守率（推奨）

| 項目 | 内容 |
|---|---|
| 分かること | 作業の最後の報告が、スキルの `## 報告` の定めた項目と順序になっているか |
| 求め方 | 採点役が、最後の返答が `## 報告` の定めに従っているかを判定し、従った実行の割合 |
| 測り方 | grader |
| 向き | 高いほど良い |
| 既定の閾値 | 1.000 |
| 前提 | — |

## `files_agreement` 変更ファイルの一致度

| 項目 | 内容 |
|---|---|
| 分かること | 同じ依頼に対して、誰が実行しても同じファイルを作り・変えるか |
| 求め方 | 課題ごとに、実行どうしの変更ファイルの集合の Jaccard 係数を総当たりで平均する |
| 測り方 | machine |
| 向き | 高いほど良い |
| 既定の閾値 | 0.800 |
| 前提 | budget.agents が 2 以上 |

## `cost_usd` 1回の実行の費用（推定、ドル）

| 項目 | 内容 |
|---|---|
| 分かること | 1つの依頼をこなすのに、サブエージェントの分も含めてどれだけの費用がかかるか |
| 求め方 | 実行の記録の result の total_cost_usd（推定）を、実行ごとに平均する |
| 測り方 | machine |
| 向き | 低いほど良い |
| 既定の閾値 | 2.000 |
| 前提 | — |

## `duration_sec` 1回の実行の時間（秒）

| 項目 | 内容 |
|---|---|
| 分かること | 1つの依頼をこなすのに、どれだけの時間がかかるか |
| 求め方 | 実行の記録の result の duration_ms を秒にし、実行ごとに平均する |
| 測り方 | machine |
| 向き | 低いほど良い |
| 既定の閾値 | 900.000 |
| 前提 | — |

## `launches` サブエージェントの起動回数

| 項目 | 内容 |
|---|---|
| 分かること | 1つの依頼で、サブエージェントを何回起動するか（多すぎると費用と時間が増える） |
| 求め方 | メインのセッションが Agent ツールでサブエージェントを起動した回数を、実行ごとに平均する |
| 測り方 | machine |
| 向き | 低いほど良い |
| 既定の閾値 | 10.000 |
| 前提 | — |

## 独自の指標（`custom_<番号>`）

一覧に無い観点は `custom_1` のような id にし、`criterion` に、採点役が「満たした / 満たしていない」で判定できる1文を書く。
値は、満たした実行の割合になる。向きは高いほど良い。
