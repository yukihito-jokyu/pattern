# forge-build

このスキルは、承認済みの charter（目的・ゴール・指標・評価課題）から、対象のオーケストレーションスキルの初版を作る。作るものは「バンドル」と呼ぶ、次の組である。

- スキル: `.claude/skills/<スキル名>/SKILL.md`（と `references/`）
- サブエージェント: `.claude/agents/<スキル名>-<役>.md`

作業は2段に分かれ、各段の最後に人が確かめる。

1. **設計**：設計役が、役・手順・人に確かめる場面・報告の項目を design.json に書く。補助 CLI が形を検査し、人が承認する
2. **構築**：補助 CLI が設計から骨組みを書き、構築役が骨組みを埋めて下書きにする。補助 CLI がバンドルの決まり（[references/bundle-rules.md](references/bundle-rules.md)）で検査し、人が承認すると、下書きをリポジトリの `.claude/` に入れる

どの段階にいて次に何をするかは、補助 CLI の `status` が決める。あなたは `status` の指示に従って、コマンドを実行するか、サブエージェントを起動するか、人に聞く。段階を自分で判断して飛ばさない。

## 役割

| 役 | サブエージェント | 受け持つこと |
|---|---|---|
| 設計役 | `forge-designer` | charter とリポジトリを読み、design.json を書く。形は [references/design-schema.md](references/design-schema.md) |
| 構築役 | `forge-builder` | 承認された設計と骨組みから、下書きのバンドルを書く |

メインのセッション（あなた）は、補助 CLI の実行、サブエージェントの起動、人との対話だけを受け持つ。設計と下書きを自分で書かない。

## 手順

1. 引数で `target-id` を受け取る。無ければ `python3 .forge/forge.py targets` で作業領域の対象の一覧を出し、AskUserQuestion で選んでもらう
2. `python3 .forge/forge.py status --target <id>` を実行し、出力の `次:` の行に従う。終えたら `status` に戻る。下の「繰り返すこと」の表のとおりに進め、`段階:` が forge-build の段でなくなるまで繰り返す
3. `段階:` に `（forge-goals）` が付いたら、`/forge-goals` で charter を決めるよう伝えて終える
4. `段階:` に `（forge-run）` が付いたら、スキルが入ったことと、次は `/forge-run <id>` で評価と改善を始めることを伝えて終える

### 繰り返すこと

| 出力の行 | すること |
|---|---|
| `次: python3 .forge/forge.py ...` | そのまま Bash で実行する。出力に `WARN` があれば、人に見せる |
| `次: 下の job をすべて Agent ツールで…` | 下の「サブエージェントの起動」に従い、続く `job` の行をすべて起動する。全員が終わったら `その後:` のコマンドを実行する |
| `次: <design.md> を人に見せ、承認するかを聞く` | 下の「人に確かめること」の設計の確認に従う |
| `次: <bundle-check.md> と <下書き> を人に見せ、入れるかを聞く` | 下の「人に確かめること」の下書きの確認に従う |
| `問題が出たら:` | `その後:` か `次:` のコマンドがエラーで問題の一覧を出したときに、この行に従う |

### サブエージェントの起動

`job` の行は `job <エージェント名> <ラベル> <プロンプトのパス>` の形をしている。1行につき1回、Agent ツールを次の値で呼ぶ。

| Agent ツールの引数 | 値 |
|---|---|
| `subagent_type` | `<エージェント名>`（`forge-designer` か `forge-builder`） |
| `description` | `<ラベル>` |
| `prompt` | `次のファイルを読み、その指示に従ってください: <プロンプトのパス>` |

- `run_in_background` は false にし、完了を待ってから次へ進む
- 返答は `完了: <パス>` の1行である。中身の確認は補助 CLI が行うので、返答を読んで判断しない
- 検査のコマンド（`design-check`、`bundle-check`）がエラーで問題の一覧を出したら、同じ `job` を、`prompt` の末尾に `前回の問題: <問題の一覧>` を足して起動し直し、同じコマンドをやり直す。2回続けて落ちたら、問題を人に見せて判断を仰ぐ
- サブエージェントが書くべきファイルを、あなたが代わりに書かない

## 人に確かめること

- 設計の確認：`design.md` の役・手順・人に確かめる場面・報告を見せ、AskUserQuestion で「承認する（推奨）／直したい」を聞く。承認なら `承認なら:` のコマンドを実行する。直したいなら、直してほしいことを文章で聞き、返ってきた文をそのまま `直すなら:` のコマンドの `<直してほしいこと>` に入れて実行する（文の中の `'` は `’` に置き換える）。既定: 人が答えられないときは、承認せずに止まる
- 下書きの確認：`bundle-check.md` のファイル・サブエージェント・手順の一覧と、下書きの SKILL.md の全文を見せ、AskUserQuestion で「入れる（推奨）／直したい」を聞く。入れるなら `承認なら:` のコマンドを実行する。直したいなら、設計の確認と同じく文章で聞き、`直すなら:` のコマンドに入れて実行する。既定: 人が答えられないときは、入れずに止まる
- `WARN` の行と、上の表に無いエラー：内容を人に見せ、判断を仰ぐ。既定: 人が答えられないときは止まる

## 報告

最後の返答に、次の項目をこの順で書く。

1. 対象（`target.id` とスキル名）
2. 入れたバンドルのファイルの一覧
3. 人が直してほしいと言ったことと、直した回数
4. 次に呼ぶスキル（`/forge-run <id>`）

## してはいけないこと

- 設計と下書きを、自分で書いたり直したりすること。直すのは設計役と構築役で、人の言葉は `--feedback` で渡す
- 人の答えを待たずに `design-approve` や `install` を実行すること
- `.claude/` に、自分でファイルを写すこと。入れるのは `install` だけである
- charter を書き換えること。charter を変えるときは `/forge-goals` に戻る
