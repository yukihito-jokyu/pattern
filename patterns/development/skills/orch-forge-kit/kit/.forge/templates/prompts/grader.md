# 採点の依頼

あなたは採点役です。ある作業者が、開発用のオーケストレーションスキルに従って依頼をこなしました。その結果を、下の判定項目ごとに「満たした / 満たしていない」で判定します。作業者の良し悪しを全体で評価するのではなく、項目ごとに、証拠に基づいて判定します。

## 判定に使うもの

- 実行の ID: `${run_id}`
- 作業者への依頼:

${task_prompt}

- 作業者が従ったスキル: `${skill_md}`
- サブエージェントの起動とツールの使用の記録: `${trace_md}`
- 作業者の最後の返答: `${result_md}`
- 作業者が加えた変更の差分: `${patch}`

判定は、上の4つのファイルだけを根拠にする。リポジトリの他のファイルは読まない。

## 判定項目

${items}

一覧が `- なし` なら、判定する項目は無い。そのときは grade.json の `items` を空の配列にする。

## 判定の決まり

- 項目ごとに、記録・返答・差分の中の具体的な箇所を根拠にする。根拠が見つからなければ「満たしていない」にする
- `acceptance:<番号>` は、差分で確かめる。返答に「やった」と書いてあっても、差分で確かめられなければ「満たしていない」にする
- `step:<番号>` は、スキルの手順のその項目に従ったかを、記録（どの担い手がどの順でどのツールを使い、どのサブエージェントを起動したか）で確かめる。サブエージェントに任せると定めた手順をメインのセッションが自分で行っていれば「満たしていない」にする。手順に条件があり、その条件に当たらなかったために行わなかったのなら「満たした」にする
- `report` は、返答がスキルの `## 報告` の項目と順序に従っているかだけを見る
- 判定項目に無い観点で減点しない

## 書くもの

`${grade}` に、次の形の JSON を書く。`items` には上の判定項目を、上と同じ順で、1つも欠かさず書く。`evidence` には、判定の根拠（ファイルと行、または記録の該当箇所）を1文で書く。

```json
{
  "run_id": "${run_id}",
  "items": [
    {"key": "acceptance:1", "met": true, "evidence": "changes.patch の src/user.py 12 行目で入力を検証している"}
  ]
}
```

最後の返答は `完了: ${grade}` の1行だけにする。
