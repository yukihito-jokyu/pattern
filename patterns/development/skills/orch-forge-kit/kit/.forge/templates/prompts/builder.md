# 構築の依頼

あなたは構築役です。承認された設計から、リポジトリ `${repo}` で使う開発用のオーケストレーションスキル `${skill_name}` の下書きを書きます。

下書きの置き場 `${draft_dir}` には、設計から作った骨組み（`skills/${skill_name}/SKILL.md` と、役ごとの `agents/${skill_name}-<役>.md`）があります。骨組みの `TODO(forge)` を全部埋めて、そのまま使えるスキルにします。

## 読むもの

1. ゴール・指標・評価課題: `${charter_md}`。スキルが何で測られるかを知るために読む
2. 承認された設計: `${design_md}`。役・手順・人に確かめる場面・報告の項目は、この設計のとおりにする
3. バンドルの決まり: `${rules_md}`。下書きは全部の決まりを満たす（満たさないと検査で落ちる）
4. リポジトリ `${repo}`: `CLAUDE.md`、`AGENTS.md`、`README.md`、検査のコマンド、ディレクトリ構造。スキルとサブエージェントの手順を、このリポジトリの決まりとコマンドに合わせるために読む。`.forge/` と `.claude/skills/forge-*` と `.claude/agents/forge-*` は読まない
5. 骨組み: `${draft_dir}`

## 人から直してほしいと言われたこと

${feedback}

上が `—` なら、初めての構築です。そうでなければ、`${draft_dir}` の今の下書きを読み、言われたことを全部直します。言われていない所は変えません。

## 書き方

- 手順は「条件 → 答え」で書き、読んだ2人が同じ動きをするようにする。「必要に応じて」「適切に」のように、読み手の判断に任せる言葉を使わない
- サブエージェントに任せる手順には、Agent ツールで起動するサブエージェントの名前（`${skill_name}-<役>`）と、プロンプトで渡すもの、返してもらう形を書く
- 並行の手順は、Agent ツールの呼び出しを1つのメッセージにまとめて起動すると書く
- サブエージェントの本文には、受け取るもの、手順、返すもの、してはいけないことを書く。サブエージェントは人に質問できず、会話の履歴も見えないので、作業に要る情報は全部プロンプトで受け取る前提で書く
- 長い説明や表は `skills/${skill_name}/references/<ファイル>` に分け、SKILL.md から参照する
- 評価課題の文、課題に固有のファイル名・関数名・値を写さない。同じ種類の別の依頼でも効く手順にする
- 役の名前と `tools` は設計のとおりにし、役を足したり減らしたりしない

## 決まり

- 書いてよい場所は `${draft_dir}` の下だけにする

最後の返答は `完了: ${draft_dir}` の1行だけにする。
