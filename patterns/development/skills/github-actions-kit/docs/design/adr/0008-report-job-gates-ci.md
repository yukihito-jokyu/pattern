# 0008 処理時間の報告と CI の合否を、ci.yml の最後の report ジョブ1つにまとめる

- 状態：採用
- 関係するルール：OPS-01、PROC-02、DEP-05

## 背景

依頼には「各ジョブ・各ステップの処理時間を PR に表示する機能」があった。GitHub にはこれを PR に出す公式の仕組みが無い。REST API の `GET /repos/{o}/{r}/actions/runs/{id}/attempts/{n}/jobs` で、1回の試行の全ジョブとステップの開始・終了の時刻を取れる（research.md の「GitHub REST API」）。

あわせて、ブランチ保護の必須チェックに何を指定するかも決める必要があった。ジョブを足すたびに必須チェックの設定を変えると、設定し忘れたジョブが落ちてもマージできてしまう。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 各ジョブの最後のステップで、自分のジョブの時間を出す | ジョブごとに閉じる | 全体の待ち時間とジョブの並びが分からない。ステップを全ジョブに足す必要がある |
| `workflow_run` で別のワークフローから報告する | 報告が CI の時間に入らない | `workflow_run` は既定のブランチの権限で動き、危険である（DEP-03） |
| 外部の報告用アクション | 作らずに済む | DEP-04 の許可表に足す必要があり、PR にコメントする権限を外部のコードに渡す |
| ci.yml の最後に report ジョブを置き、全ジョブの後に REST API から1回で取る。合否も needs の結果で決める | 全ジョブの時間を1回で正確に取れる。必須チェックを report の1つにできる | report ジョブの `needs` を全ジョブにそろえる必要がある |

## 決定

`ci.yml` の最後に `report` ジョブを置く。`if: ${{ !cancelled() }}` で、ほかのジョブが失敗しても動く。`./.github/actions/run-report` が時間を集計してジョブサマリーと PR のコメントに出し、`needs` に失敗か取り消しのジョブがあれば失敗で終わる。ブランチ保護の必須チェックは `report` の1つにする。

## 理由

全ジョブが終わった後に1回で取るのが、時間を正確に取れる唯一の方法である。合否を report にまとめると、ジョブを足しても必須チェックの設定を変えずに済み、足し忘れたジョブの失敗も report が拾う。`needs` のそろえ忘れは、構造の検査（`rules_ops.py` の `ops01_report`）が落とす。

## 影響

- `ci.yml` のジョブを足す・消すときは、report の `needs` を同じ変更で変える（PROC-02）
- report ジョブは `pull-requests: write` を持つ。フォークの PR ではトークンが読み取り専用なので、コメントせずに通知だけを出す
- run-report は `ci.yml` の report ジョブだけで使う。ほかのワークフローの時間はジョブサマリーの標準の表示で見る
