# 0002 基盤の名前を github-actions-kit にし、iac と cli-library の分野として扱う

- 状態：採用
- 関係するルール：STR 節、DEP 節、KIT 節

## 背景

依頼は「GitHub Actions のワークフローを作成・更新するスキル」で、玄人の書き方、各ジョブ・各ステップの処理時間を PR に出す機能、ベストプラクティスを含めることだった。基盤の名前と、揺れの軸を選ぶための分野（pattern-foundation の domain-profiles）を決める必要があった。

GitHub Actions のワークフローは、宣言的な YAML で CI の基盤を組み立てるもので、権限・環境・state の分け方が書き方の中心になる。一方で、この基盤は検査の CLI と composite アクションという、配布して使ってもらう道具も持つ。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| iac だけ | 権限・環境・ラベルの軸が揃う | CLI の出力と終了コード、公開面の互換性の軸が抜ける |
| cli-library だけ | 道具の作り方の軸が揃う | ワークフローの権限と環境の軸が抜ける |
| iac と cli-library | 両方の軸を拾える | 軸の数が増える |

## 決定

名前は `github-actions-kit`（技術名 + 道具一式の `kit`）にし、分野は iac と cli-library の2つにする。GitHub Actions に固有の軸（トリガー、参照の固定、更新の方式、処理時間の報告、キャッシュと成果物）は X6〜X10 として足す。

## 理由

ワークフローの書き方の揺れ（権限、environment、ランナーのラベル）は iac の追加の軸がそのまま当てはまる。検査の CLI と run-report は配布先で使われる道具なので、cli-library の軸（終了コードと出力の形、公開面の互換性）が要る。

## 影響

- ルールは2種類に分かれる。STR〜TOOL 節はワークフローの書き方で配布する。KIT 節はキットの開発だけのルールで配布しない（[0003](0003-two-distributed-skills.md)）
- 分野を足す・減らすときは、rules.md の「追加した軸」の表と、対応するルールを見直す
