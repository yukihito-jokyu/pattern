# 0005 ワークフロー依存ロックファイルが GA になるまで、外部アクションを SHA で固定する

- 状態：採用
- 関係するルール：DEP-06、PROC-03

## 背景

外部アクションの参照をタグで書くと、タグが別のコミットに移されたときに別のコードが動く。2026-10-14 に、GitHub はワークフロー依存ロックファイル（`.github/workflows/actions.lock`）を public preview として出し、依存の固定の最善策をロックファイルにした。SHA の固定は次善策の扱いになった（research.md の「調べた時点で、書き方に大きく響いた変化」）。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| タグで参照する | 読みやすい | タグの移動で別のコードが動く。zizmor の `unpinned-uses` が落とす |
| ワークフロー依存ロックファイル | 公式の最善策。推移的な依存も固定される | preview で、書式と動きが変わりうる。actionlint と zizmor の対応が確かめられない |
| 40 桁のコミット SHA と `# vX.Y.Z` のコメント | 検査の道具と Dependabot が対応している。GA の機能だけで完結する | 推移的な依存（composite アクションの中の参照）は固定できない |

## 決定

SHA の固定を採る。SHA は記憶から書かず、`gha pin <owner/repo>` が `git ls-remote --tags` から解決したものを写す。ロックファイルが GA になり、actionlint と zizmor が対応したら、この ADR を置き換えて移る。

## 理由

preview の機能をルールの土台にすると、変わったときに全部の配布先が一度に壊れる。SHA の固定は、zizmor の `unpinned-uses`（`hash-pin`）と構造の検査（DEP-06）で機械で縛れ、Dependabot が SHA とコメントを一緒に更新できる。

## 影響

- composite アクションの中で使われる推移的な依存は固定されない。DEP-04 の許可表で使うアクションを絞ることで補う
- 移るときは、DEP-06 と PROC-03 を書き換え、`gha pin` をロックファイルの生成に置き換え、参照実装を作り直す
