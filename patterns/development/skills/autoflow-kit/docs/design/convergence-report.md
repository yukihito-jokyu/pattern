# autoflow-kit 収束テストの記録

独立エージェント（この基盤の作成時の会話履歴を持たないセッション）に同じ課題を解かせ、書き方の違い（揺れ）を測った記録である。手順の詳細は、作成に使ったスキルの convergence-test.md にある。各ラウンドの生データは `.foundation/convergence/round-<R>/` にある。

## 条件

| 項目 | 値 |
|---|---|
| 実行方法 | `claude -p`（Claude Code 2.1.296）。`--permission-mode acceptEdits`、`--no-session-persistence`、`--allowedTools` は Skill と `make`・`python3`・`git diff`・`git status` などの読み取りのコマンドだけ。各コピーの CLAUDE.md・スキル・hooks（manifest の status は ready）を読む |
| エージェントの人数 | 3人（並列3） |
| 課題 | `.foundation/convergence/tasks.json`（T1-add：H1 の条件を足す、T2-change：レビューの観点を足す、T3-cross：探索役の指摘に項目を足して2か所に出す、H1-holdout：取得元を足す） |
| 合格基準 | 全員の出力が check を通る、files = 1.0、names ≥ 0.8、R1〜R6 の未対処が0件、ホールドアウトでも同じ、レビュー検出率が全員 100% |

## レビュー検出率

レビュー用スキル `review` に、違反を1つずつ仕込んだ10件の seed（`.foundation/convergence/review-seeds.json`）を未コミットの変更として渡した。TOOL-03 の1件は機械の検査（guard）が落とし、残りの9件は `make check` を全部通る形で、レビューでしか見つからない。

| エージェント | 検出率 | 余計な指摘 | 判定 |
|---|---|---|---|
| review/agent-1 | 1.000（10/10） | なし（CODE-04・DEP-03・PROC-04・TEST-01 は、指摘の理由や「該当なし」の確認の中で触れただけ） | 差し戻し |
| review/agent-2 | 1.000（10/10） | なし（CODE-04・GATE-01・TEST-01 は同上） | 差し戻し |
| review/agent-3 | 1.000（10/10） | なし（CODE-04・PROC-04・TEST-01 は同上） | 差し戻し |

検出したルールIDの集合は、3人で一致した。3人とも「ルール追加の提案」に、同じ点（テストのメソッドを既存の `<モジュール>Test` クラスに置くか、新しいクラスを作るかがルールで決まっていない）を挙げた。seed の作り方（`SourceJiraTest` という新しいクラス）を見て出た提案で、実装役の12人は誰も新しいクラスを作っていない。

## 結論

3ラウンド（33セッション、費用の合計 $45.72）で、次の基準を満たした。

- 課題を解いた全員の出力が check を通った（30セッション全部。残りの3セッションはレビューの検出率の測定）
- 最終ラウンドの全課題で files = 1.000（ホールドアウトを含む）
- names は、T1・T2・ホールドアウトで 1.000
- レビュー検出率は全員 100%、検出したルールIDの集合も一致

満たさなかった基準は1つで、最終ラウンドの T3-cross の names（0.422）である。原因は、新しい JSON の項目名の英訳の語順（`suggested_fix` と `fix_suggestion`）で、R2 に分類した。上限の3ラウンドに達したので、ここで止めた。対処の案は次の2つで、どちらを採るか（あるいは受け入れるか）はユーザーの判断に残す。

1. 実装用スキルの既定値表に「新しい名前は、英語の語順（修飾語が先、中心の名詞が最後）で書く（`suggested_fix`、`other_locations`、`bug_class`）」を足し、T3 だけをもう1ラウンド（3セッション）測る
2. 項目名は依頼から決まらない値なので、依頼を出す人が名前を書くか、実装役が報告の「決めた値」に書いたものを人が H3 で確かめる運用にし、R7 として受け入れる
