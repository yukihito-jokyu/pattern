# 0003 配布するスキルを3つ、サブエージェントを5つにし、配布物を kit/claude に置く

- 状態：採用
- 関係するルール：STR-01、STR-05、GATE-02、GATE-07

## 背景

オートフローには、人と話す場面（準備の承認、関所、最終承認）と、人と話さずに進む場面（計画、実装、レビュー、リスクの判定）がある。サブエージェントからは AskUserQuestion が除かれる（[research.md](../research.md) の「Claude Code のサブエージェント」）。記事は、差分を新しいコンテキストのエージェントがレビューし、複数のエージェントが並列に探し、別のグループが投票するとする。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| スキル1つに全部を書く | 入口が1つ | 準備と学びの手順が毎回読み込まれ、SKILL.md が500行を超える |
| スキルを準備・実行・学びの3つに分け、役ごとにサブエージェントを定義する | 呼ぶ場面と読む量が分かれる。役ごとに道具を絞れる | ファイルが増える |

## 決定

- スキルは `autoflow-setup`（H0）、`autoflow`（H1〜H3）、`autoflow-learn` の3つ。全部 `disable-model-invocation: true` にし、人が `/名前` で呼ぶ
- サブエージェントは計画役（`autoflow-planner`）、実装役（`autoflow-builder`）、探索役（`autoflow-finder`）、検証役（`autoflow-verifier`）、リスク判定役（`autoflow-risk`）の5つ。`tools` を列挙し、`Skill` と `Agent` を入れない。実装役だけが Edit を持つ
- 探索役は観点（`policy.LENSES`）ごとに、検証役は人数ぶん、同じ定義を別のプロンプトで並列に起動する
- 配布物の正本は `kit/claude/`（先頭にドットを付けない）。この基盤自身の `.claude/`（開発用の impl・review スキルと hooks）と混ざらないようにするため

## 理由

自動で呼ばれるスキルは、人の知らない間に作業ブランチを作りうる。役を分けると、読み取りだけの役の前後で tree を比べる確認（GATE-07）を役ごとに置ける。

## 影響

役を足すときは `contracts.AGENTS`、`kit/claude/agents/`、ひな形、`status` の job の行を一緒に変える（PROC-02）。
