# 0010 プロファイルとレビューの既定値を厳しめにする

- 状態：採用
- 関係するルール：GATE-01、PROC-06

## 背景

記事は「リスクの段を書き出す。作者ではなく変更から決め、厳しめに始めて証拠に応じて緩める」とし、ラウンドの上限を3にしている。プロファイルの既定値は、人が H0 で承認する前の案になる。

## 決定

既定値で決めた事項として、次の値にする。値の正本は `profile.DEFAULTS` と `policy` の表である。

| 項目 | 既定値 | 根拠 |
|---|---|---|
| 常に人が見るパス | CI の設定、認証・課金・決済、マイグレーション、秘密情報、`.autoflow/`・`.claude/`・`CLAUDE.md`・`AGENTS.md`・`REVIEW.md` | 記事の「billing, the auto-updater and CI workflows」。オートフロー自身の規則を変える変更も人が見る |
| 高リスクのパス | 依存の一覧と lockfile、Dockerfile、IaC | 依存の追加は「作るかどうか」の判断に当たる |
| 低リスクのパス | `docs/**`、`*.md`（上の2つに当たらないもの） | 記事の「Low: Docs, copy」 |
| 大きい差分 | 400行を超えたら少なくとも medium、1,000行を超えたら high | 記事の「1,000行超の PR のほとんどに指摘がある」 |
| 修正の試行の上限 | 検査の失敗が3回続いたら H2 | ラウンドの上限と同じ値にそろえた |
| レビューのラウンドの上限 | 3 | 記事の「After three rounds」 |
| 計画の範囲の上限 | 20ファイルを超えたら H1（分けることを提案する） | 記事の「変更を小さくする」 |
| 投票 | low は検証役2人で2票、medium と high は3人で2票 | 記事の「enough of them agree」。過半数にした |

## 理由

緩い既定値で始めると、見逃しが出てから締めることになる。厳しい既定値は、H0 の承認で人が緩められる。

## 影響

既定値を変えるときは、`profile.DEFAULTS`・`policy` の表を変え、`make docs` を回す。配布先の承認済みのプロファイルは変わらない。
