# 0009 実行の進み具合を追記だけの記録で持ち、補助 CLI の状態機械が次の段を決める

- 状態：採用
- 関係するルール：STATE-01、GATE-03、GATE-04

## 背景

オートフローは、実装 → 検証 → レビュー → 実装（指摘の修正）→ … と繰り返す。ファイルの有無だけで進み具合を求めると、繰り返しの何回目か、どの版の検証か、人が何を決めたかが分からない。進み具合を AI に覚えさせると、関所を飛ばしうる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| ファイルの有無から求める | 状態のファイルが要らない | 繰り返しと人の決定の順序を表せない |
| 今の段を `state.json` に上書きで持つ | 読みやすい | 上書きの途中で壊れると戻せない。過去の判断の根拠が残らない |
| 出来事を `trail.jsonl` に追記し、純粋な関数 `trail.next_step` で次の段を求める | 順序と根拠が全部残る。状態機械を表のテストで確かめられる。`metrics` もこの記録から数えられる | 出来事の種類を足すとき、状態機械も直す |

## 決定

3つ目を採る。各段の入口は `context.begin` で `next_step` を求め、番でなければ止まる（GATE-03）。`next_step` は今の tree も受け取り、最後の検証の後に tree が変わっていれば `verify` を返す（GATE-04）。人の関所は `escalate`（H2 の理由）と `decided` の出来事で表す。

## 理由

追記だけの記録は、どの順で何が起きたかを後から辿れ、記事の「人の時間を測る」「ガードレールを測る」の材料にもなる。

## 影響

段を足すときは、`trail` の定数と `next_step` の分岐から作る（PROC-01）。
