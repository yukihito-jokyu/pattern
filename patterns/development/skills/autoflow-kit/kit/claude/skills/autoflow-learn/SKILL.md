# autoflow-learn

見逃しや手戻りを、その実行だけで直して終わりにしない。AI が何を知らなかったかを考え、次の実行が読む場所（CLAUDE.md、REVIEW.md、プロファイル、検査）を直す。ゴールは、差し戻しとインシデントを増やさずに、人の時間を減らすことである。

## インシデントを記録する

引数が `incident <実行の id> <見つかった問題>` なら、`python3 .autoflow/autoflow.py incident --run <実行の id> --text '<見つかった問題>'` を実行し、続けて「材料を集める」へ進む。

## 材料を集める

1. `python3 .autoflow/autoflow.py metrics` を実行し、人の決定の回数、最初の H3 で承認された割合、差し戻し・中止・インシデントを読む
2. `python3 .autoflow/autoflow.py learn` を実行し、繰り返したバグの種類、退けた指摘、人の直しの依頼、H2 に当たった条件、インシデントを読む
3. 必要なら、実行の記録（`.autoflow/runs/<id>/` の報告書、レビューの結果）を Read で読む

## 直す案を作る

材料ごとに、次の表で直す場所を選び、案を作る。案には、根拠（どの実行の、どの指摘や回答か）と、直す文面を書く。

| 材料 | 直す場所 |
|---|---|
| 同じバグの種類が繰り返し出る | CLAUDE.md（書き方の決まり）か、そのバグを落とす検査（lint のルール、テスト） |
| レビューが見逃した（インシデント） | REVIEW.md（必ず確かめること）、`risk.always_human`、検査 |
| 退けた指摘が多い観点・種類 | REVIEW.md（指摘しないこと） |
| 人の直しの依頼が同じ方向 | CLAUDE.md（方向の決まり）、計画の受け入れ条件の書き方 |
| H2 の検査の失敗が多い | 検査コマンド、テストの書き方の決まり |
| 差し戻しもインシデントも無く、H3 が常に1回で承認される段がある | プロファイルの上限やパスの分類を緩める案（証拠に応じて緩める） |

## 人に確かめること

1. 案を一覧にして示す（直す場所、文面、根拠）
2. AskUserQuestion（複数選択）で、取り入れる案を選んでもらう
3. 選ばれた案だけを Edit で直す。プロファイル（`.autoflow/profile.json`）を直したら、/autoflow-setup の setup-check と承認（H0）をやり直すよう人に伝える

回答が無い・空・自動で閉じた質問は、承認にも選択にもしない。関所のファイルの場所を報告して止まる。

## してはいけないこと

- 人が選んでいない案を直す
- `.autoflow/runs/` の記録を書き換える
- コミットする（直した変更のコミットは人が行う）
