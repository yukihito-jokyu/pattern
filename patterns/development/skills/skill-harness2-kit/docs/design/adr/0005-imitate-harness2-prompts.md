# 0005 harness2 のプロンプトを、構造と強調を保って日本語に移す

- 状態：採用
- 関係するルール：STATE-02、STATE-03、STATE-04、STATE-05

## 背景

harness2 の制御の多くは、コードではなくプロンプトの文にある。例えば、INV と DOM の境界の問い、証拠の重みの付け方（1/k の欠陥は雑音）、notes の形（kept|revised|dropped -> 編集 -> 根拠）、選択の基準の順番、振り返りの評価語（helped / hurt / no observed effect / confounded）である（research.md の「harness2 の仕組み」）。論文のアブレーションでは、次元の分け方（scoping）を外すと最も大きく下がる。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| 独自のプロンプトを書く | スキルに合わせやすい | harness2 の効いている制御が抜け落ちる |
| 英語のまま写す | 原文に忠実 | 利用者（日本語）が監査で読めない。スキルの部品に読み替えていない |
| 構造・見出し・強調・判定の問いを保ったまま日本語に移し、部品の名前だけをスキルに読み替える | 制御を保ったまま、利用者が読める | 訳の誤差が入りうる |

## 決定

3つ目を採る。ひな形は `kit/.h2/templates/prompts/` に置き、各ひな形の先頭のコメントに元の場所（prompts.py の行）を書く。次の語は訳さずに残す：`KEEP_BASE`、`NO_ENTRY`、`INV`、`DOM`、`helped`、`hurt`、`no observed effect`、`confounded`、`kept`、`revised`、`dropped`、`<notes>`、`<why>`、`choice`。これらは `contracts` が文字列で読むからである。

harness2 のプロンプトには、1つの作業場所に合わせる adapt の版と、同じ領域の後のタスクにも使う tts の版がある。土台は adapt の版を移し、次の2節だけを tts の版から移す。

| 節 | 採る版 | 理由 |
|---|---|---|
| 一般化（`_generalize.md`） | tts の `_TTS_GENERALIZE`「一般化し、暗記しない」 | 採用したスキルは利用者のこれからの依頼すべてで動く。adapt の版の「この作業場所の事実を書き込む」をスキルに入れると、タスク固有の事実が全依頼の文脈を食う |
| 証拠の読み方（`_how-to-read.md`） | tts の `_TTS_HOW`「同じ条件の実行どうしの違いが信号」 | 基準の実行は同じスキルで k 回動くので、違いがスキルの決めていない所を示す。さらに「スキルが呼ばれなかった実行は無いか」の問いを1行足した。harness2 の「読み込まれなかったスキルの編集は何も変えていない」を、Claude Code の Skill の呼び出しに読み替えたものである |

選択は adapt の版の `select()` を、候補を完成品だけにする形（`pool_kind = finals`）と形への適合を全部問う形（`selection_conformance = full`）で移す。

## 理由

制御を文として保つことが、harness2 を模倣する中心だからである。返答のタグを英語のまま残すと、モデルの返答の形が揺れにくく、`contracts` の読み取りも単純になる。

## 影響

harness2 のプロンプトが変わったら、元の場所のコメントを手がかりに差分を移す（PROC-02 の対応表）。
