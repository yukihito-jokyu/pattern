# 0004 harness を対象スキルのディレクトリに読み替え、編集面を4種類に絞る

- 状態：採用
- 関係するルール：STATE-06、STATE-04、STATE-05

## 背景

harness2 の harness は8つの部品（システムプロンプト、ガードレール、記憶、ツールの説明、スキル、サブエージェント、スクリプト、プラグイン）を持つ木で、部品ごとに「いつ文脈に入るか」と費用が違う。編集面は SurfaceSpec（パスの正規表現）で決まり、外のファイルは捨てられる。この基盤の改善対象は、利用者のリポジトリの Claude Code スキル1つである。

## 選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| リポジトリの CLAUDE.md・hooks・サブエージェントまで編集面に入れる | harness2 の8部品に近い | 対象が1つのスキルではなくなり、採用の影響がリポジトリ全体に及ぶ。hooks は利用者の環境で自動で動くコードになる |
| 対象スキルのディレクトリだけを編集面にし、frontmatter の `description` 以外を固定する | 採用の影響がスキルに閉じる。`name` や `allowed-tools` の書き換えによる権限の拡大が起きない | hooks（harness2 のプラグインに当たる、読み飛ばせない仕組み）を使えない |

## 決定

編集面は `SKILL.md`、`references/<名前>.md`、`scripts/<名前>.py`・`.sh`、`assets/<名前>` の4種類にする。部品と harness2 の対応は次のとおりである。

| スキルの部品 | いつ文脈に入るか | harness2 で当たるもの |
|---|---|---|
| frontmatter の `description` | 常に（全セッションのスキルの一覧） | 常時の文（ALWAYS ON） |
| SKILL.md の本文 | スキルが呼ばれたとき、全文 | スキルの本文 |
| `references/<名前>.md` | 本文が読むように言ったときだけ | 必要なときだけの部品（ON DEMAND） |
| `scripts/<名前>` | 実行したとき。出力だけが文脈に入る | スクリプト |
| `assets/<名前>` | 開いたときだけ | — |

frontmatter は `description` 以外の行を元の木と同じに保つ。`` !` `` の記法（読み込み時にシェルを実行する）は元の木より増やさない。テキストでないファイルや編集面の外のファイルを持つスキルは、`check` が対象にできないと報告する。

## 理由

- harness2 の「ALWAYS-ON PROSE IS THE EXPENSIVE OPTION」は、スキルでは description に当たる。description は全セッションで文脈を使い、一覧で切り詰められる（research.md の「Claude Code のスキル」）。部品の対応を表にして編集者に渡すと、harness2 の部品の優先順をそのまま移せる
- `` !` `` の記法は、harness2 の「常時の文の `{{` は実行の前に描画で落ちる」と同じく、実行の前に評価される危険な書き方である。増やせると、採用の後に利用者の機械でコマンドが動く

## 影響

- hooks とサブエージェントを使う改善はできない。必要になったら、この ADR を置き換えて編集面に足す（`skilltree` の編集面、`validate`、`_surface.md`、STATE-06 を一緒に変える）
- 画像などのテキストでない assets を持つスキルは対象にできない
