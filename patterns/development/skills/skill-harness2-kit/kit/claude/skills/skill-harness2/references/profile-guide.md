# profile.json の書き方

`init` が書いたひな形 `.h2/targets/<対象>/profile.json` を、人と決めた値で埋める。書いたら `check` で検証する。check は問題を全部まとめて返すので、1つずつではなく一度に直す。

## 前提：文の項目はどこに入るか

文の項目（`work` など）は、編集者・合成役・選択役のプロンプトのひな形にそのまま入る。編集者は答えを見ずにスキルを直すので、文の項目には「何をする仕事か」と「実務家がよいと考える進め方」だけを書き、「どう測るか」を書かない。`work`・`inv_levers`・`dom_levers`・`yardstick`・`selection_checks` に次の語があると check が拒む。

`benchmark`、`evaluation`、`grader`、`rubric`、`score`、`採点`、`正解`、`スコア`、`ルーブリック`、`評価基準`、`ベンチマーク`

## 人と決める項目

| 項目 | 決めること | 例 |
|---|---|---|
| `work` | 対象スキルが受け持つ仕事を、実務家の言葉で1〜3文 | 「社内の議事録を、決まった見出しと日付の形に整えて渡す」 |
| `domain_word` | 仕事の分野を表す短い名詞。ひな形の「この〜の依頼」に入る | 「議事録の整形」 |
| `deliverable_word` | 成果物を表す短い名詞 | 「整えた議事録」 |
| `k` | 1〜5。基準の実行と、各次元の編集者の数。費用は k に比例する | 2 |
| `modes` | `parallel`（幅）、`sequential`（深さ）、または両方 | `["parallel"]` |
| `rollout.model`、`improver.model` | 実行と編集に使うモデル。空なら `claude` の既定 | `""` |
| `rollout.max_budget_usd`、`improver.max_budget_usd` | 1回の上限（米ドル）。`plan.md` の上限の合計はこれから計算する | 1.0、2.0 |

k とモードの選び方は次のとおりである。

| 状況 | k | modes |
|---|---|---|
| 初めて試す、費用を抑えたい | 1 | `["parallel"]` |
| 通常 | 2 | `["parallel"]` |
| 前のラウンドの候補が似通っていた（show の多様性が 1.0 に近い） | 2〜3 | `["sequential"]` |
| 幅と深さを比べたい | 2 | `["parallel", "sequential"]` |

## 既定のままでよい項目

| 項目 | 意味 | 変える場面 |
|---|---|---|
| `schema_version` | profile.json の形の版。1 | 変えない |
| `skill` | 対象スキルのディレクトリ（リポジトリからの相対パス）。init が書く | 変えない |
| `inv_levers` | INV の編集者への手がかり（この仕事で効く手順や道具） | 人が「この点を見てほしい」と言ったとき |
| `dom_levers` | DOM の編集者への手がかり（この分野の実務家の知識） | 同上 |
| `yardstick` | この仕事でのよい進め方。編集者と合成役に「よい進め方」として見せる | 人が実務の基準を持っているとき。点数の付け方は書かない |
| `selection_lead` | 選択役の決め方の先頭（0番）に置く1文 | 成果物の比べ方に最優先の観点があるとき |
| `selection_checks` | 選択役に「この仕事での正しさの意味」として見せる文 | 成果物の正しさに分野固有の意味があるとき |
| `seed` | タスクの順。`null` なら名前の順、整数ならその種でシャッフル | タスクの順による偏りを避けたいとき |
| `width` | 並行に動かす数（1〜8） | 利用の上限に当たるときは下げる |
| `obs_trunc` | 軌跡の1つの観測を切り詰める文字数（10000 以上） | 下げない。10000 未満は、編集者が切り詰めを欠陥と取り違えるため拒む |
| `deliverable` | 成果物を出したとみなす条件。`files`（作業場所のファイルを足すか変えた）、`reply`（返答がある）、`any`（どちらか） | 対象スキルの成果物がファイルだけ、または返答だけのとき |
| `claude` | `claude` を呼ぶコマンド（配列） | `claude` が PATH に無いとき |
| `rollout.tools` | 実行に許す道具。`Skill` は補助 CLI が必ず足す | 対象スキルが他の道具（`WebFetch` など）を使うとき |
| `rollout.timeout_sec`、`improver.timeout_sec` | 1回の時間の上限（30〜7200 秒） | 時間切れが続くとき |
| `improver.effort` | 編集のセッションの考える深さ。`""`、`low`、`medium`、`high`、`xhigh`、`max` | 費用を抑えたいとき、深く考えさせたいとき |
| `leak_globs` | 答えに当たるファイルのパターン。証拠に写さず、材料にあれば check が拒む | 材料と同じディレクトリに模範解答を置いているとき |

## 書いた後

`python3 .h2/h2.py check <対象>` を実行する。`plan.md` に回数と費用の上限が出るので、人に見せて承認を聞く。承認の後に profile.json を変えると、`run` は止まる。変えたら check からやり直す。
