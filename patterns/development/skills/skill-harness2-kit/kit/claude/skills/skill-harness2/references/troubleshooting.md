# エラーと対処

補助 CLI のエラーは `エラー: ` で始まり、終了コード 1 で終わる。エラーの文の言葉でこの表を探す。

## 準備と承認

| エラーの文の言葉 | 原因 | 対処 |
|---|---|---|
| `は既にあります` | init を2回実行した | profile.json を直して check を実行する。作り直すなら profile.json を消してから init |
| `SKILL.md がありません` | `--skill` か profile.json の `skill` が対象スキルのディレクトリを指していない | リポジトリからの相対パス（例 `.claude/skills/<名前>`）にする |
| `測定の語` | 文の項目に採点や評価の語がある | 実務家の言葉で仕事を書き直す（`profile-guide.md` の「前提」） |
| `obs_trunc は 10000 以上` | 切り詰めを小さくしすぎた | 10000 以上にする。証拠はファイルで渡すので、小さくする必要は無い |
| `schema_version` | 古い形の profile.json | 新しい init のひな形と見比べて項目を合わせ、`schema_version` を今の版にする |
| `編集面の外にあるか、UTF-8 で読めません` | 対象スキルに `SKILL.md`・`references/`・`scripts/`・`assets/` 以外のファイルがある | そのファイルを対象スキルの外へ移すか、人に相談する。採用で消えるため扱えない |
| `採点の印`、`leak_globs に当たります` | task.md か材料に、答えや採点の出力に当たるものがある | 答えを材料から外す。外せないなら `leak_globs` に書く |
| `plan.md が今の profile.json と tasks/ と合いません` | check の後に profile.json か tasks/ を変えた | check を実行し、新しい plan.md を人に見せ直す |

## 実行

| エラーの文の言葉 | 原因 | 対処 |
|---|---|---|
| `承認がありません` | approve をしていない | check → 人の承認 → approve |
| `承認の後に profile.json が変わりました`、`tasks/ が変わりました` | 承認の後に手で変えた | 元に戻すか、check から承認をやり直す |
| `承認の後に対象スキルが変わりました` | ラウンドの途中で対象スキルを変えたか、既に採用した | 採用済みなら新しいラウンドを始める。手で変えたなら check から |
| `を起動できません` | `claude` が PATH に無い | profile.json の `claude` に実行ファイルのパスを書く |
| `台帳が予算の恒等式に合いません` | 実行かセッションの数が R = 4k、P = 3k に合わない（補助 CLI の不具合） | `runs/r<N>/<task>/<モード>/` を消さずに残し、補助 CLI の不具合として報告する |
| `答えに当たるものがあります` | 証拠の木か候補に採点の印が入った | 印の一覧を広げて黙らせない。印がどこから入ったか（材料、前の judge の記録）を直す |

## 結果がおかしいとき

| 様子 | 原因 | 対処 |
|---|---|---|
| どの完成品も「成果物 なし」 | 実行が成果物を出していないか、`deliverable` の条件が合っていない | 実行の `runs/r<N>/<task>/<モード>/rollouts/<label>/trajectory.md` を読む。返答だけを出すスキルなら `deliverable` を `reply` にする |
| 「スキルの呼び出し」がすべて「なし」 | 実行でスキルが呼ばれていない | `disable-model-invocation: true` のスキルなら task.md の先頭を `/名前` にする。そうでなければ description が依頼に合っていない |
| 全部の段が「落ちて入力の木に戻った」 | 編集のセッションが失敗している | `sessions/<label>.a1/stderr.txt` と `reply.md` を読む。時間切れなら `improver.timeout_sec` を上げる |
| 全部の完成品が KEEP_BASE | 実行どうしに分かれ目が無く、証拠が変更を支持しなかった | 失敗ではない。タスクを増やすか、対象スキルが苦手な依頼を足す |

## 利用者のスキルが実行に混ざっていないかを確かめる

実行は `--setting-sources project` で、利用者のスキル（`~/.claude/skills/`）とプラグインを除いて動かす。この振る舞いは Claude Code の版によって変わりうる。Claude Code を上げた後は、`runs/r<N>/<task>/base/rollouts/base1/trajectory.md` の先頭の `[SYSTEM] 開始:` の行の `skills=[…]` を見る。対象スキルと Claude Code に同梱のスキルだけが並んでいれば正しい。利用者のスキルの名前があれば、結果がそのスキルの影響を受けているので、人に伝える。
