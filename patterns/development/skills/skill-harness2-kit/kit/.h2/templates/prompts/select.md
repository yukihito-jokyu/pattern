# 決め方（この順で）

${selection_lead}

1. 渡すもの。指示が名指しする${deliverable_word}がすべて、求められた場所に、求められた形で、名指しされたすべての部分とともにあるか。

2. 形への適合。求められたものだけか。指示が項目・列・シート・節・順番を名指ししているなら、それが成果物の形を決め、形は依頼の一部である。余分な列、余分なシート、足した説明の行、名前や言い回しを変えた見出し、結合した題の行、並べ替えた項目は、どれほど役立って見えても改善ではなく逸脱である。後で読む人や取り込む仕組みは名前と位置そのものを手がかりにし、意図を尋ねられない。指示がはっきりしているなら正確に合わせ、指示が無いなら、満たす中で最も素直な形を選ぶ。
   依頼が求める値は、値としてなければならない。読み手に計算し直させる成果物（数の代わりの表計算の式、埋めるべき印、説明だけで実行していない計算）は、その値を渡していない。

3. 忠実さ。主張を `context/source/` と照らし合わせる。そこに仕事の材料がある。開いて、候補が述べる事実・データ・名前・数値・制約を確かめる。候補の言葉をうのみにせず、権威があるように聞こえるかで済ませない。でっち上げの具体は退ける。候補どうしが食い違うなら材料が決める。材料が何も言っていないなら、自信をもって穴を埋めた候補より、そう述べた候補を選ぶ。

4. 内部の整合。成果物はそれ自体と合っているか。行と合う合計、要約とその元の表とで合う数値、解決する相互参照、実際にある項目の数と合う件数。同じ成果物の中で別の数と矛盾する数は、どちらが誤りか分からなくても欠陥である。

5. 実際の使いやすさ。正しい種類の成果物で、意図した人や仕組みが、欠けた仕事を組み立て直さずに使い、動かし、開き、取り込み、それに基づいて動けるか。納得したいレビュアーとしてではなく、依頼した人の後工程として判断する。人が読みやすくなる追加でも、取り込みを壊すなら利点ではなく費用である。

6. 仕上げ。埋めるべき印、TODO、未解決のメモ、壊れた参照、空の必須項目、目に見えて未完の節、宣言した形式に合わない中身が無いか。この比較のために描画の側が入れた切り詰めの印は、元の成果物の欠陥ではない。実際に見えるものだけで判断する。

長さと磨き込みは、それ自体では長所ではない。短く、正しく、完全で、形の正確な答えは、穴や飾りのある長い答えにまさる。
